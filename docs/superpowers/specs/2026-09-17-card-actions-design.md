# CCoder 0.2.18：清空会话 / 压缩上下文（状态卡上的两颗按钮）

日期：2026-09-17　分支：`v0.2.18-dev`　`pluginVersion=0.2.18`
设计稿：`docs/design/card-actions.html`（形态）+ `docs/design/card-action-icons.html`（图形）
**方案乙（常驻角标）**；四个决定已拍（见 §5），图形选了清空 = A 扫把 / 压缩 = E 压进托盘

---

## 1. 要解决的问题

用户原话：

> 我想在连接卡片里加个按钮，点击后清空本次会话内容，在上下文卡片里加个按钮点击后可以压缩上下文，
> 这样就不用敲指令了。

功能本身**两件都已经通了**：

- `/clear` 的整条路 0.2.13 就实现了（`ClaudePanel.kt:2412-2432`：init 换 id → 清转写区 →
  标签退回「新会话」→ 会话列表重载 → 用量归零 → 系统提示）
- `/compact` 是一条现成命令，`/` 补全里就有

缺的只是**入口**：两颗按钮都藏在"你得知道打 `/clear`"后面。这一版做入口，**不做功能**。

形态试了两轮才定：先是**悬停换值**（鼠标移上来才把值行画成按钮，实现完被真机否掉，见 §3 的改版记录），
现在是**常驻角标**（右上角一颗小图标，永远在那儿）。设计稿里另外画过但没选的：卡内第三行
（四张卡一起从 50px 长到 68px，把 v2 省下的高度退回一半）、详情浮层（两步，且连接卡今天没有浮层）。

## 3. 交互（**方案乙：常驻角标**，2026-09-17 傍晚改）

> **改版记录。** 上午定的是方案甲「悬停换值」，实现完装到真机上被用户否掉：
> 「鼠标放在边框上按钮才出现，挪到中间就消失，我无法点击」。根因是子件的 tooltip ——
> `JComponent.setToolTipText` 会把 `ToolTipManager` 注册成**那个子件的鼠标监听器**，
> 子件于是成了事件目标，指针一进卡片中间卡片就收到 `mouseExited`，悬停态当场结束。
> 用户当场定了方案乙（设计稿 `docs/design/card-actions.html` 里那一版），并挑了图形
> （见 `docs/design/card-action-icons.html`：清空 = A 扫把，压缩 = E 压进托盘）。
>
> **方案乙把这个问题从根上消掉**：图标常驻，它的存在不依赖任何悬停状态。

### 3.1 两颗图标常驻在右上角

- 位置：卡片内边距的右上角，**命中区 16×16**、图形画约 14px（与左上角那四个卡片图标同尺寸）
- **常驻**：有动作就画，不看悬停 —— 可不可点只取决于 `enabled`
- 指针压上去：底色亮起来（danger 色 / 强调色，透明度 `0x2E`）+ 手型光标 + tooltip 换成动作说明
- 值行**不动**：永远显示模型的值（「已连接」/「42%」），动作文案只进 tooltip

第 3 条是这一版的代价也是它的诚实之处：卡片上只有图形，没有文字说明动作是什么 ——
所以 tooltip 从"补充"变成了**唯一的文字出口**，必须挂得住（见 §4 的 tooltip 规矩）。

### 3.2 自绘，**不新增组件**

与 `CardIconView`、`IndicatorView` 同一套路数：`paintComponent` 里画，点击按几何判。
三条理由，缺一不可：

1. **平台图标是固定颜色**，而这两颗要跟着"可用/不可用/悬停"变；何况扫把与托盘平台里根本没有
2. **多一个 `JComponent` 就多一个事件目标**，还要给它挂 tooltip —— 而挂了 tooltip 就等于
   把它变成事件目标（上面那条改版记录）。不新增组件，这类坑一次都不踩
3. **画出来的和能点的天然是同一块**（同一个 `actionIconBounds()`），两者不会分家

### 3.3 点击路由

`mouseClicked` 里按几何分流（纯函数，可测）：

| 点在哪儿 | 连接卡 | 上下文卡（以及子任务 / 子代理） |
|---|---|---|
| **右上角那 16×16 命中区** | 执行动作 | 执行动作 |
| 卡的其余部分 | 什么也不做（今天如此） | 开详情（今天如此） |

判据是**命中的位置**，不是"悬停过" —— 点击不依赖任何悬停状态。
这条是清空不设确认框（§5 决定三）的安全垫：误触得正好点中那一格，不是随手一点。

### 3.4 两颗图标的规格

| | 连接卡 · 清空 | 上下文卡 · 压缩 |
|---|---|---|
| 图形 | 扫把（细柄 + 实心帚头） | 压进托盘（向下的箭头 + 浅斗） |
| 常态色 | 次要色（与卡面其它元素同族，不抢注意力） | 同左 |
| 悬停色 | **danger**（会丢上下文） | 强调色（`focusColor`） |
| 常态提示 | 副值（`12.3k / 200k` 这类，与今天一字不差） | 同左 |
| 悬停提示 | 开一条新会话，上下文清空 —— 当前这条留在磁盘上，会话列表里能切回 | 把这段对话压缩成摘要，腾出上下文空间；界面上的记录不动 |
| 忙时提示 | 会话空闲时可清空 | 会话空闲时可压缩 |

**为什么扫把不是垃圾桶**：垃圾桶承诺"删掉"，而这个动作**不删任何东西** ——
旧会话留在磁盘上、列表里能切回来，它只是把台面扫干净。语义差一档，图标就不能图省事。

### 3.5 三态

可用条件 = **会话就绪（`ready`）且空闲（`!busy`）且不在压缩中**。三个都是"不是"就灰掉：

| 态 | 图标 | 可点 | 说明 |
|---|---|---|---|
| 空闲 | 常色 | ✓ | |
| 忙（`busy`） | **灰的** | ✗ | 提示改说"会话空闲时可清空" |
| 未就绪（启动中 / 启动失败 / 已断开） | 同上，灰的 | ✗ | 会话都不在，点了也没得发 |
| 压缩中（仅上下文卡） | **整个不画** | ✗ | 值行让给「压缩中…」（Warn 色）—— 见 §3.8 |

**压缩中的判据取 CLI 的 status 事件**（事实 8、9），不取"我们刚发了什么"：
自动压缩（`trigger:'auto'`）也要能在卡上看见，而那种情况我们没发过任何命令。
与权限模式读回同一条规矩：**CLI 报的实况是权威**。判据只认 `status:"compacting"`
（`requesting` 每回合都有，事实 9）；结束认 `status:null` + `compact_result:"success"`，
不等 boundary（boundary 更晚，见事实 11 —— 卡上的"压缩中"不该多挂一秒）。

**一处待定的紧**：连接卡忙态里有一档标签是四字「等待响应」，实测它与右上角图标之间
只剩 **3px**（探针 `build/status-cards-probe-actions-waiting.png` 量的）。不重叠，但紧。
两条路：把那一档的标签缩成「等待中」，或给标签行让出角上的位置（标签会略偏左）。
**用户尚未拍，实现按"不动文案、不动布局"落的。**

### 3.6 清空：不写第二套逻辑

按钮点击 → 走**与输入框发送完全相同**的那条路（把 `/clear` 当一条消息发出去）：

```
按钮 → sendText("/clear") → lastSendWasCommand=true → CLI 执行 → init 换 id
     → 既有的 §5.2 切换动作（清转写区 / 标签 / 列表 / 用量 / 系统提示）
```

实现上把"发一条文本"从 `sendCurrentInput()` 里抽成两处都能调的入口即可，
**清空的清理动作一行都不新写** —— 那种"两条路各清各的"迟早会出现两套不一致的状态。

### 3.7 压缩：回执只由 `compact_boundary` 产生

压缩完成 → 转写区追加一条系统提示：

| 情况 | 文案 |
|---|---|
| 字段齐全 | 已压缩上下文：**31.5k → 1.9k**（用时 10s） |
| 缺 `post_tokens` | 已压缩上下文（压缩前 31.5k） |
| 缺 `duration_ms` | 省略括号，其余照写 |
| `trigger:'auto'` | 前缀改「CLI **自动**压缩了上下文：…」 |

- 数字用现成的 `formatTokenCount`，不用新写法
- **手动点的那次也只由 boundary 产生这一条** —— 点击侧不另发。单一事实来源，
  免得出现"提示说完了而 CLI 其实还在压"
- 缺字段照降级写，不猜（事实 3 里三个字段两个是可选的）
- ⚠️ **两种字段形状都要认**（事实 12）：实时事件 snake_case、落盘历史 camelCase。
  回执既要在现场出现、也要在恢复出来的历史里出现（回放同样走 `MessageRenderer`）——
  只认一种，就会变成"现场有、历史里没有"这种最不容易被发现的半边功能

### 3.8 上下文卡在压缩中的样子

值行从「42%」换成「压缩中…」，色调 Warn，底下的比例条同步转 Warn 色 ——
与连接卡忙态同一族（过渡态），不与"上下文正常"抢同一种绿/蓝。
压缩结束（boundary 到达）后百分比自己会跳（`requestContextUsage` 那条路不变）。

## 5. 四个已定的决定（用户 2026-09-17 拍）

| 决定 | 取值 | 理由（用户已认可） |
|---|---|---|
| 忙时点得动吗 | **灰掉不可点** | 压缩正在跑的会话语义暧昧（压"此刻之前"还是"跑完以后"说不清）；清空会把进行中的回合连根拔了。**输入框敲命令的入口保持原样**（照排），按钮走严格档 |
| 压缩支持自定义指令吗 | **先不带**，一键直发裸 `/compact` | 按钮服务的是"高频、无参数"的那一次；要带说明本来就能敲 |
| 清空要确认框吗 | **不弹**，按钮用 danger 色 | 沿用 composer 版的决定（误触代价低：旧会话在磁盘上）。§3.3 的"只有那 16×16 命中区才算动作"是它的安全垫 |
| 压缩完的数字接不接 | **接** | 这是唯一能让用户判断"这次压缩值不值"的信息，数据已在事件流里；把 2026-09-13 §8 记的"本次不做"还上 |

## 6. 明确不做

- **自定义压缩指令**（`/compact <说明>`）—— 决定二
- **忙时排队** —— 决定一
- **清空确认框 / 行内二次确认** —— 决定三；真被误触过一次再补（会话列表删除那套，不新做模态）
- **压缩的进度条** —— CLI 只给 `requesting / compacting` 两个离散状态，没有百分比。不造刻度
- **第五张卡或新的按钮排** —— "加卡是拿宽度换的"（`StatusCardsRow.kt` 注释里那次教训）
- **连接卡的详情浮层** —— 丁方案没选
- **键盘快捷键** —— 两颗图标就是入口；快捷键等有需求再说
- **清空的撤回** —— 清空后回不去（旧会话在磁盘上，用会话列表切回，今天的语义不变）
