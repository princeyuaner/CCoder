# 输入框里的图：点一下放大看

日期：2026-09-17　分支：`v0.2.20-dev`　`pluginVersion=0.2.20`
状态：**已实现**

---

## 1. 用户原话

> 输入框中粘贴了图片后，能不能点击后放大查看？

## 2. 缺口：一处已经存在的不对称

**发出去之后**在转写区点图，早就能放大看 —— web 那层 `ImageLightbox`：压暗的浮层、Esc 关、
←/→ 与数字键翻页。**输入框里还没发的那几张点不动**：只有右上角 14px 的 ✕ 管用，
点缩略图正文什么都不会发生。

这条口子 2026-09-13 是**特意划掉**的（`2026-09-13-paste-image-design.md` §13「明确不做的」
第一条：「不做图片点击放大/查看原图」），当时的理由是"缩略图只有 56px，要做就得再引一个
看图的地方"。现在补回来，因为：

- 56px 的职责只是"认出是哪张"，而附件带自己的注释里写着**粘错比粘不上更常见**；
- 放大查看同时就是**发送前的最后一眼** —— 而这一眼该看的是**将要发出去的那份字节**，
  不是界面上的缩略图。

## 3. 方案

### 3.1 点哪儿

| 位置 | 行为 |
|---|---|
| ✕ 圆点（右上角，边长 `BADGE_SIDE` = 14） | 移除这张图（不变） |
| 缩略图正文（其余 56×42） | **打开放大查看**（新） |

判定抽成纯函数 `thumbHit(x, y, w, h, badgeSide): ThumbHit { REMOVE, OPEN }` ——
原来是长在私有类 `ThumbView` 里的 `internal fun inBadge`，**用例根本够不着**
（private 类的成员对测试文件不可见）。这次一并修：`ThumbView` 改 `internal`，
带子给一个 `thumbViewAt(i)` 让用例能派发真事件。

顺带修一条：**只认左键**。现在 `mouseClicked` 不判键，右键点 ✕ 也会把图删掉。

### 3.2 看的是哪份图

`AttachedImage.bytes` —— **将要发给 Claude 的那一份**（长边 ≤1568，PNG 优先，超标才转
JPEG），点击时 `ImageIO.read` 解回来（`previewImageOf`）。

| 候选 | 为什么不 |
|---|---|
| 56px 的 `thumb` | 放大就是糊的 —— 那一份的使命只是"认出是哪张" |
| `transcriptDataUrl`（推给转写区那份） | JPEG q85，且要先过一次 base64 解码 |
| 常驻一份缩放前的位图 | 1568px 一张 ≈ 5.5MB，四张 22MB，五个标签页翻倍 —— 为一个"可能点"的动作常驻内存不值 |

解出来的图**只活在框里**（对话框自己的缓存），关掉就没了。

### 3.3 在哪儿看

`DialogWrapper`（仓库里第五个：`PermissionDialog` / `ChangelogDialog` / `SettingsDialog` /
`AskQuestionDialog` / 本框）：可拉伸、Esc 关、按钮栏一颗「关闭」。

**不做"在编辑器里打开"**：那要把它落成一个临时文件、还要管清理 —— 转写区那个浮层的
注释里已经写过同一条理由：此刻的问题只是"这是不是那张"。

### 3.4 多大

- 开框尺寸 = 图按 `fitScale` 缩进**屏幕可用区的 80%**；
- 框被拉大时图跟着放大，但**永不超过 1:1**（超过原图只是把像素摊开，越看越糊）；
- 比框小就居中留白，底色用主题面板色（不做 web 那种压暗 —— 那层浮层是因为网页里
  没有窗口装饰才需要）。

```kotlin
internal fun fitScale(imgW, imgH, boxW, boxH): Double = min(1.0, boxW/imgW, boxH/imgH)
```

屏幕尺寸由调用方去问（`Toolkit.getScreenSize()` + 兜底），**纯函数收的是数字**，
所以用例直接打。

**翻页不重新定尺寸**：四张图尺寸可能不同，每翻一张就换窗口大小是跳的。
尺寸在开框时按第一张定下来，后面的图缩进同一个框里。

### 3.5 多张时翻页

←/→ 翻页、数字键 `1..4` 直跳（与转写区那个浮层同一套手感），图 > 1 张时左下角一行
小字「2 / 4 · ← → 翻页」；只有一张时那一行不出现（一行空白不该白占高度）。

**已知风险**：Swing 的焦点系统在某些 LAF 下会吃掉左右键。数字键不受影响，所以最坏的
情况下翻页还有一条路；真机冒烟时专门试一次。

## 4. 接线

- `AttachmentStrip` 加 `var onPreview: (List<AttachedImage>, Int) -> Unit`。
  写成**属性而不是构造参数**：[onChanged] 那条"建带子时面板还没拿到输入卡"的理由一样，
  另外构造参数加在后面会把既有用例 `AttachmentStrip { changes++ }` 的尾随 lambda
  抢走（尾随 lambda 绑的是**最后一个**参数）。
- `ClaudePanel.buildUI`：`attachments.onPreview = { images, index -> showImagePreview(project, images, index) }`
  —— opener 单独一个函数，照 `showChangelogDialog` 的写法，探针与用例能换掉。
- 框是模态的，开着的时候输入区冻着，所以不存在"看着看着图被发出去"。

## 5. 验证

- **纯函数**：`thumbHit`（四个角 + 边界那一像素）、`fitScale`（钳在 1.0、极端长宽比）、
  `previewImageSize`（屏幕 80% 封顶、小图不放大、比例不变）、`previewImageOf`
  （真 PNG 解得出、坏字节返回 null）
- **附件带真事件**：派发 `MouseEvent` —— 点正文 → 回调拿到 `(images, 0)`；
  点 ✕ → 图没了**且回调没被叫**；右键点 ✕ → 什么都不发生
- **出图** `ImagePreviewRenderProbe`：大图（缩进框）、小图（1:1 居中）、四张（提示行）
- **看图只回答三件事**：四周留白舒不舒服、提示行抢不抢戏、小图 1:1 时框是不是小得可笑

## 6. 实现记录（2026-09-17）

Kotlin 1457 全绿（新增 20：`ImagePreviewTest` 14 + 附件带 3 + 探针 3）。

**探针打印的数**（`ImagePreviewRenderProbe`，本机屏幕 1728×1080，那八成就是 1382×864）：

| 这张 | 图（发送那份） | 放大区首选 | 出图 |
|---|---|---|---|
| 大图 | 1568×980 | **1382×864** | 1402×884 |
| 小图 | 300×200 | **360×260**（地板） | 380×280 |
| 四张 | 1568×980 | **1382×883** | 1402×903 |

四张那次多出来的 19px 就是提示行 —— 与"一张时不显示"对得上（同一张图，一张时是 864）。

**§5 那三个问题的答复**：留白匀称（大图按比例铺满、小图四周留白一致）；提示行不抢戏
（小字、灰、左下角 —— 加了 6px 边距之后才这么说）；小图 1:1 的框**不小得可笑**
（360×260 的地板托着）。

**出图之后改的两处**：

1. 提示行左边加 6px：图铺满放大区时那行小字紧贴画面左缘，看着像被裁掉半截。
2. 提示行的**文案与可见性提前到 `init()` 之前**摆好。pack 是平台做的，而我们
   `init()` 之后才点亮那一行 —— 万一 pack 就发生在 `init()` 里，那 19px 没算进去，
   行会被压扁。不压这个注：全部初始化器都排在 `init()` 前面。

**键盘**：←/→ 与数字键都绑在 `rootPane` 的 `WHEN_IN_FOCUSED_WINDOW` 上（框里焦点
多半在「关闭」那颗按钮上）。数字键是左右键万一被焦点系统吃掉时的退路 ——
真机冒烟时要专门试一次。

## 7. 明确不做

另存为 / 复制回剪贴板 / 双击进编辑器 / 滚轮缩放（zoom）—— 都超出"看一眼是不是那张"。
框上也不做"上一张 / 下一张"按钮：键盘就够，多两颗按钮会把这一屏的重点从图挪到控件上。
