# 上下文卡：进度不再是"一条 2px 的条"，而是整张卡的水位

日期：2026-09-17　分支：`v0.2.20-dev`　`pluginVersion=0.2.20`
状态：**已实现**

---

## 1. 用户原话与选择

> 这个进度条不好看，我想做成覆盖整上下文卡片的效果，出几个效果放浏览器给我选择
> （补充）要有动画效果

选型台（`web/tools/context-card.mjs` → `build/probe/context-card.html`，七个方案、深浅两色、
对比度标尺）里用户挑的是 **B · 整卡纵向水位**：从卡片底部往上涨，水面一层缓慢起伏的波纹。

## 2. 形状与颜色

- **水位由卡片自己画**（`StatusCardView.paintComponent`），不是那个 2px 的指示器：
  "卡片自己就是进度"这句话在几何上就要求如此。判定条件是 `model.indicator is Indicator.Meter`
  —— 目前只有上下文卡用 Meter，所以这条路径等于只为它服务。
- **裁到卡片圆角**：水位先 `clip` 成与描边同一个模子的圆角矩形，再填水位路径 ——
  不裁的话水会漫到四个角外面（"底比边圆"那类毛刺的又一种）。
- **颜色**：`mix(面板底, alertColor() ?: focusColor(), 0.16)` —— 与选型台上那个 0.16 一致；
  色调走既有的 `alertColor()`（70% 琥珀、90% 红），所以警告色是**同一支颜色**在管，没有第二套。
- **`IndicatorView.paintMeter` 不再画那条 2px 的条**：它的活被卡片接走了。
  尺寸契约（Meter 占 2px、指示器槽按点阵的 5px 算死）一个字不动 —— 卡片高度因此纹丝不动。

## 3. 代价：标签要从灰换成正文色

卡片一被染色，现在那个灰标签（`UIUtil.getInactiveTextColor()`）在**浅色主题**下会掉到
3.5–3.9:1（低于 4.5 标尺）—— 这是选型台上量出来的数，也是页面上写明的代价。
所以：**带水位的卡，标签用正文色**（`getLabelForeground()`），其余三张照旧是灰的。
四张并排时上下文卡的标题会略亮一点 —— 那是"它身上多了一层信息"的合理提示。

## 4. 动画：只在"有事发生"时动

| 什么时候 | 动什么 | 多久 |
|---|---|---|
| 数值变了（每轮对话都会涨） | 水位从旧值升/降到新值 | 600ms |
| 同一次变化之后 | 水面波纹跑满一个周期 | 2.4s |
| 压缩中（`CARD_COMPACTING_TEXT`） | 水位保持 + 波纹持续 | 直到压缩结束 |

**不是常驻动画。** 一趟动画跑完就 `stop()`，静止画面就停在那儿。
理由写在 `StatusCardView` 的注释里：IDE 里常驻跳动的元素很耗注意力，也让笔记本白烧 CPU；
而"水位"这个隐喻在**变化的那一刻**表达得最清楚（用户正是那一秒会看它）。
压缩中是唯一的例外 —— 那件事本来就没有确定进度，一直动才是诚实的。

计时器：`javax.swing.Timer`，33ms 一跳（≈30fps），`removeNotify` 里停掉（跟
`ComposerCard` 的焦点监听器同一条规矩：离开层级就要收干净）。

## 5. 抽出来当纯函数的部分

| 函数 | 管什么 |
|---|---|
| `waterTopY(level, height)` | 水位在第几像素（0 = 空 → 底边；1 = 满 → 顶边） |
| `waterSurfaceY(x, baseY, amplitude, waveLength, phase)` | 水面上某一点的正弦高度 |
| `stepTowards(shown, target, step)` | 一趟动画的步进（不越过目标） |
| `nextPhase(phase, step)` | 波相位（0..1 回绕） |

四条都不碰 Swing，用例直接打。

## 6. 验证

- **纯函数**：水位映射的两端与 34%；正弦在相位 0 / 1/4 处的取值；步进不越过目标；
  相位回绕。
- **画出来的像素**（`StatusCardViewTest` 里那条）：把卡画进图里，量三点 ——
  底部是水色、顶部是面板色、**左下角那一小块是面板色**（水位确实被圆角裁掉了）。
- **探针** `ContextWaterRenderProbe`：一排水位的四个相位（静图里看得见波纹）、

- Kotlin 全量跑绿。

## 7. 实现记录（2026-09-17）

Kotlin 1471 全绿（新增 7：`StatusCardViewTest` 6 + 探针 1）。探针打印：

```
面板底 #3C3F41（测试 JVM 的 Darcula；真机 New UI 是 #2B2D30）
水色   rgb(60,68,75)      ← mix(面板底, 强调色, 0.16)
34% 的水面在 y=37（卡高 56）    波幅 1.6px   波长 22px
```

**踩到的两个坑**（都记在代码注释里）：

1. **`drawRoundRect` / `RoundRectangle2D` 那对参数是直径，不是半径**：
   `arc = 16` 画出来的是**半径 8** 的圆角。写用例时按"半径 16"算左下角在哪儿，
   于是取样点落在了弧线上（量到水与描边的混色）—— 是**用例先错**，
   代码里卡片底色与水位用的是同一个 `arc`，本来就同心。取样点改成最角上那一个像素
   之后，这条断言才在钉"水位有没有被圆角裁掉"。
2. **"还没上屏"那条路不能只 `return`**：一开始只判断"没 showing 就不起动画"，
   结果是"第一次 `setModel` 早于上屏"时水位停在 0 —— 第一帧会画成一张空卡。
   改成没 showing 就**直接落到目标值**（动画留给看得见的变化）。
   用例因此能钉住一个真问题：像素那条**不调 `settleWater`**，
   靠的正是这条路径。

**动画确实非常驻**：`waterTimer` 只在"值变了（600ms + 波纹 2.4s）"或"压缩中"时跑，
跑完自己 `stop()`；`removeNotify` 里再兜一道（离开层级就收干净）。
