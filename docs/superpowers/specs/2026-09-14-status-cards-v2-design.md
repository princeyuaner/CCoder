# 状态卡 v2：两行居中 + 连接卡显示实时动作

日期：2026-09-14　设计稿：`docs/design/status-cards-v2.html` 方案甲

---

## 1. 要解决的问题

用户原话：

> 现在 连接，上下文，子任务，子代理这个卡片的 UI 很难看，太高了，而且没居中
> 选甲，同时连接信息框，我希望能实时显示当前在做什么，比如思考中，编辑文件，运行指令等等

现状（`build/status-cards-probe*.png` 量到的）：四张卡 **80px** 高，卡里叠了四层
（标签 / 值 / 副值 / 指示器），四张卡里三种对齐、三种字号；没有图标，只能靠
标签辨认哪格是什么。而顶部这排是**抬头一眼**的地方，转写区反而是滚动区。

## 2. 目标

- 卡面收到**两行**：图标 + 标签一行、值一行，**都居中**；实测 **50px**（省 37%）
- 每格一个 14px 图标，颜色跟 [Tone] 走
- **连接卡忙时改说"在干什么"**（思考中 / 运行指令 / 编辑文件…），空闲时回落成连接状态
- 一点不丢的信息：`12.3k / 200k` 进 tooltip 与详情浮层；四张卡始终在（收边不隐藏）；
  子任务 / 子代理照旧可点开详情

## 3. 卡面怎么排（方案甲）

```
┌───────────────┐
│  ⬡ 连接        │   ← 图标 + 标签，FlowLayout 居中
│   已连接       │   ← 值，铺满一行、文字居中
│ ▂▂▂▂▂▂▂▂▂▂▂▂▂ │   ← 比例条（仅上下文，贴底 2px）
└───────────────┘
```

- **副值不上卡面**，挂 `toolTipText`（**卡片与两个标签都要挂**：Swing 只弹鼠标
  底下那个组件自己的 tooltip）
- **字号统一**：值 base+1、标签 base-2。改版前是 11/12/15 三种按 `bigValue` 二选一，
  扫一眼分不出重点 —— `bigValue` 与 `leadingDot` 两个字段因此删掉
- **指示器收形**：比例条保持通长（贴底气质的来源），分段与点数收成**居中的
  小方块 / 小圆点**（改版前是一条 60px 宽的横条，在矮卡上又长又偏）
- 收边（quiet）：**边框与底照常画**，只有值与图标转灰。2026-09-14 用户明确要求过
  （"子任务、子代理没数据时候边框默认加上"）——那格是"现在没数据"，不是"没有这一格"。
  描边对象始终不变，insets 恒为 1，收边与否都不会让四张卡左右跳

## 4. 连接卡：实时动作

映射规则全在 `Activity.kt`（纯函数）：

| 渲染项 / 事件 | 卡上写 |
|---|---|
| `ThinkingDelta` / `Thinking` | 思考中 |
| `AssistantDelta` / `AssistantText` | 回复中 |
| `ToolUse` | 按工具名：运行指令（Bash）/ 编辑文件（Edit·Write·MultiEdit）/ 读取文件（Read）/ 搜索（Grep·Glob）/ 子代理在跑（Task）/ 调用工具（认不出的） |
| `ToolResult` | **不动** |
| `Result` / `ErrorItem` | 回空闲（连接文字重新上卡） |
| 权限请求到达 | 等待授权 |
| 发出消息那一刻 | 等待响应（第一口 token 可能要等几秒，那期间写"已连接"是假话） |

三处刻意的决定：

1. **工具结果不清空**：一轮是「调用 → 结果 → 思考 → 调用 …」，结果一到就清，
   卡上会在一轮中间闪一下"已连接"。只有回合结束与报错才回空闲。
2. **色调走 Warn**：它是**过渡态**，与"正在启动…""正在载入…"同一族；
   绿色只留给"已连接"这种安定状态。
3. **只走实时路径**：`replayItems` 不参与 —— 回放旧会话时最后一条可能是被中断的
   工具调用，照它显示"运行指令"会是一句假话。

写入口只有一个 `setActivity`，且**值没变直接返回**：流式期间每个 token 都会调它，
而"思考中"要连着上百次保持不动。

## 5. 图标：四个都自绘

平台图标（`AllIcons.Toolwindows.Task`、`AllIcons.General.Groups`，都核对过存在）
是**固定颜色**的，而图标必须跟着 [Tone] 变 —— 连接卡的"已连接 / 正在载入 /
启动失败"就靠这一处区分（改版前是一个前置状态点，现在并进图标了）。混着用会在
同一行里露出"系统色图标 + 主题色图标"两种画风，所以四个统一自绘（Java2D，
同 `IndicatorView` 的路子），按 16×16 方格画再整体缩放。

**四分之一饼是符号不是刻度**：6% 按比例画在 14px 的环上只有 2px 弧，看不见。
真实比例交给数字与那条底边。

## 6. 两个实测出来的坑

1. **`JLabel` 在 BoxLayout 里不会被拉满**。把值标签直接放进 Y_AXIS 的盒子，它
   拿到的宽度既不是卡片宽度、也不会随文字变化（量到 39px，而 5 个汉字要 65px）——
   `setMaximumSize(MAX, …)` 也没用。值那一行因此套一层 **`BorderLayout`** 面板
   （把 CENTER 拉满），文字靠 `horizontalAlignment = CENTER` 居中。
   第一行反过来用 **`FlowLayout`**：它天生按内容居中，而 BoxLayout 会把富余宽度
   分给子件（标签被撑开、图标挤到左边）。
2. **两行的最大高度都要锁在首选值**：不锁的话竖直富余会被它们分走，
   下面那个弹簧就没得吃，指示器贴不到底。

## 6.5 真机反馈的三处修正（同日）

装上真机之后用户报了三件事，都在这一版里修掉：

1. **"上下文的进度条没有居中"** —— 量出来是：83px 的那一行里它只占 **42px、还贴在右边**。
   根因与值那一行同一个：BoxLayout 只把**面板**拉满，指示器不是面板。指示器因此也
   套了一层 `BorderLayout`（`indicatorRow`）铺满整行；点阵与分段的**居中改在绘制里**
   算（`pipsStartX`，纯函数单测），比例条则通长。
2. **"卡片和输入框粘着"** —— 状态卡与输入区之间原本一点空隙都没有。加 7px 支柱。
3. **"背景为什么是黑的，和背景一样"** —— 卡原来是 `isOpaque = false`（透明的），
   透出来的是它坐在哪层容器上：真实 IDE 里那层是暗的，于是四张卡糊进背景、
   设计稿里的灰卡片没了。改成**自己画一层圆角底**（`UIUtil.getPanelBackground()`）——
   顺带避免"方角填充 + 圆角描边"在四个角上打架。收边的卡仍然什么都不画，
   那才是"退到背景里"。

探针跟着改了一处：把卡画在**暗底**上（编辑器底色）。画在面板灰上的话，
第 3 条在图上根本看不出来 —— 探针也得照着真实环境画，否则它证明不了什么。

## 6.6 点上下文卡看明细（同日追加）

用户："点击上下文应该显示详细的上下文信息"。

上下文卡从"不可点"变成可点，走的是子任务/子代理那一套浮层（`showTogglePopup`，
不抢焦点，点外面收起）。内容由 `buildContextDetail` 给：

```
上下文                    6%
已用      12.3k tokens
窗口      200k tokens
剩余      187.7k tokens
          还宽裕 / 过七成了… / 已经写满九成…
```

- **分母才是"还能聊多久"的关键**，而它正是改版时从卡面让到 tooltip 的那个数 ——
  这里给它一个正经位置
- 窗口未知时不编造分母，照实说"还没拿到窗口大小（不是空闲）"：与卡面显示 0
  是同一条规矩
- 浮层字段从"两张卡共用"扩成三张（`openDetail: DetailCard?`），收起时三张卡的
  高亮一起清 —— 点浮层外面关掉也走同一条

## 7. 分层

| 层 | 位置 |
|---|---|
| 动作词与映射 | `src/main/kotlin/com/ccoder/ui/Activity.kt`（纯函数） |
| 四张卡的模型 | `ui/StatusCards.kt`（`activityCardOf` 新增；删 `bigValue` / `leadingDot`） |
| 卡的排布与图标 | `ui/StatusCardView.kt`（`CardIcon` / `CardIconView` 新增，`ToneDotView` 删） |
| 四个格子的分工 | `ui/StatusCardsRow.kt`（图标由行分配） |
| 接线 | `ClaudePanel`（`activity` 字段、`setActivity`、权限与发送两个时机） |
| 离屏出图 | `StatusCardsRenderProbe`（新增活动态那一张） |

## 8. 验收

- **单测**：`ActivityTest`（映射逐条、结果不动、只有回合结束回空闲、动作词都 ≤6 字）、
  `StatusCardsTest`（活动卡的标签/值/色调）、`StatusCardViewTest`（副值改挂 tooltip、
  图标跟色调走、收边变灰、图标按构造参数不看数据）、`StatusCardsRowTest`
  （四张卡各带各的图标、八种连接文字 + 长动作词都放得下、等宽、最小高度）
- **离屏出图**：`build/status-cards-probe*.png` 五张（忙 / 空闲 / 最长连接文字 /
  没用量 / **正在运行指令**），卡片高 **50px**（原 80px）
- **人工**：真机里看一眼图标在深浅色下的观感，以及跑长任务时卡上是否真的
  实时在变（这条只有装上去才知道）

## 9. 不做

- **整排降不透明度**（我的建议，用户没点头）：空着时整排 50% 淡出、状态一来亮起。
  没做 —— 现有的收边（灰值 + 透明边）已经够安静，一句话就能加
- 不做"点连接卡看当前动作的详情"：那句话本身就是全部内容
- 不动协议、不动转写区：本次全在 Swing 侧
