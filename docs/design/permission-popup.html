权限与提问：改成弹出窗口

现在两者都是插在工具窗口底部固定槽位里的卡片（spec §6.3）。要改成弹窗，形态有四种走法。 本页把四种都画出来，连同"提问有多题时一题一弹"的样子，供选定后落 spec 与实现。

前提：改的是形态，不是规矩

为什么改。卡片住在工具窗口里，窗口没开着就看不见（今天靠粘性通知兜）；卡片位置在消息流下方， 长对话里会被滚走。弹窗把"有人在等你"直接放到屏幕前面，与工具窗口开着与否无关。

三条硬规则一条都不放松（spec §6.2，来自 SDK 明文）： ①永远要 resolve —— 关窗即拒绝，不是"稍后再问"； ②不能被误触批准 —— 焦点落在「拒绝」上，批准不绑任何键盘快捷键，回车不算批准； ③「本会话不再询问」只在 SDK 允许时渲染（不是渲染后禁用）。

一条要重新拍的旧决定。spec §6.3 原文写着"明确不做：升级为模态对话框"。 方案 B 就是模态 —— 选它就得改那句话，选 A / C / D 则那句话继续成立。

不设超时（§6.6）：宁可让 Claude 等，也不给一个无来由的拒绝。所以"怎么让人一定看得见"是这页的全部重点。

方案 A

右下角悬浮窗

把槽位里那张卡片原样搬进一个非模态小窗，一次一张，弹在 IDE 右下角。 卡片的身体（主文案 / 路径 / 原始输入 / 三个按钮）一行都不用改。

  val next = queue.activateNextIfIdle()

方案 C

门控与收尾

  • 没答完不给提交。少答一题就提交，等于替用户答了 —— 而那个答案会被当成"用户的选择"喂回模型。
  • 提交后：弹窗换成消息流里一行"已作答：…"（今天的 note 行为不变），窗口关闭。
  • 窗口关掉 / 按 Esc = 拒绝整条提问，不是"下次再问"（规则①）。
  • 「本会话不再询问」不出现在提问弹窗上 —— 提问不是授权请求，自动"允许"等于把问题吞掉（PermissionOptions.autoAllowApplies）。

四个方案摆在一条线上比

权重最高的一列是"会不会漏看" —— 因为 Claude 等起来没有超时（§6.6），漏看一次就是无限等待。

要你拍板的四件事

  1. 形态选哪个（A / B / C / D）。我的倾向是 A：它是你这次要求的直译，改动最小，且没有一条规矩要放松；C 是"并行请求多"时的加强版。
  2. 多题提问的"弹"法：同一个窗口换内容（不闪、不跳），还是关掉一个再弹下一个（"弹出"感更明确）？
  3. 选项自带的 preview 要不要一起渲染（第 2 题那张图的右半边）。今天解析了没画。
  4. 若选 B，spec §6.3 末句"明确不做：升级为模态对话框"要改 —— 那是你上一轮定的，得你点头才能翻。
