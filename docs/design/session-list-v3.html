历史会话：从列表到卡片

你原话是「这个历史会话页面不好看，改为卡片式的」。卡片式说白了是拿高度换可读性： 每条会话从"表格里的一行"变成"一张有身体的小卡"。这一页把高度预算摆在台面上， 再给三种花法 —— 差别在一张卡放几行、一屏还看得见几条，不在配色好不好看。

已选定（2026-09-22）：方案 A · 单行卡。 落地的是：卡高 32 + 缝 4（= 一张 36px 高）、圆角 arc 16（半径 8，与输入卡 / 状态卡 / 设置卡同一个数）、底取 cardFill()、悬停取列表选中那一档的"弱"版本；当前会话 = 强调色描边 + 左侧 3px 强调条 + 标题加粗（改版前那个 ✓ 由强调条顶掉， 顺带省下标题左边那 13px 的占位）。被别的标签占着的那条整卡压暗到 55% —— 只把卡底调灰 是看不出来的，出图试过。浮层高度上限没动：一屏 8 张（8 × 36 = 288，与改版前 10 × 28 = 280 同一档），所以"看见的条数"从 10 变 8，浮层本身没有变高。B / C 两条没有上。 实现见 ui/SessionList.kt 的 SessionCard。 内容上下居中那两处（2026-09-22 用户报的「文字没有上下居中」）：卡片的缝一半留在上边 （卡片若贴着顶画，它的中线比内容的中线高 2px）；行尾那一串（＋/时间/删除）外面套一层 GridBagLayout 居中 —— FlowLayout 是把行贴着顶摆的，卡片一高，它就高出去 4px。 图见 SessionListRenderProbe 出的那几张（这次它改用真机 LAF 出图了）。

三案共用的卡片语法

这一层不投票：它是这个仓库已经有的卡片语言（输入卡 ComposerCard、状态卡 StatusCardView、设置卡 SettingsCard 三处同一个模子）， 照用即可，不另创几何。

共用 · 几何

卡 = 圆角 8 + 描边 + 一点点底

  • 圆角 arc 16（半径 8）：与输入卡、状态卡、设置卡同一个常量 CARD_CORNER_ARC。
  • 底比页面亮/暗 5%（CARD_TINT=0.05）：深色主题下卡比底亮一档、浅色下暗一档，方向不用判明暗。卡片靠边 + 圆角读出来，不靠色差堆。
  • 描边取 Component.borderColor，与转写区那些分界线同一支灰。
  • 悬停：底换成列表选中那一档的"弱"版本（getListSelectionBackground(false)），描边提到强调色。

方案 A · 单行卡（省地儿）

一张卡里放原来那一行的全部内容，只是给它一个身体。

方案 A

一行内容，卡高 32

卡里仍是 勾/强调条 + 标题 + 时间 + 删除 一条线，只是外面套了卡：圆角、底、4px 缝。 标题是唯一可伸缩的元素，长标题照旧打省略号。

好处

  • 密度只掉三成：一屏 7 张（现状 10 行，同一 288px 预算）。
  • 改动最小：行里那几个部件一个不动，改的是壳 —— 现有那 40 多条列表用例基本照旧。
  • 扫视节奏没变：还是一行一条，位置固定，找"第几个"靠数数就行。

代价

  • "卡片感"最弱 —— 如果嫌它只是"行加了个框"，那就该看 B。
  • 标题与时间仍然在同一行抢宽度：标题 ≈300px（B 是 ≈340px）。

落地要点

  • 卡高不是新数：删除按钮 22 + 上下各 5 = 32；缝 4。
    可用高 288 − 8（列表内边距）− 26（表头） = 254 → 254 ÷ 36 ≈ 7 张
  • 现成的件：RoundedLineBorder + cardFill()（两者 arc 必须同源，否则四角露出月牙）。

方案 B · 双行卡（信息分层）

标题独享一行，标签、状态与操作搬到第二行 —— 信息各就各位，代价是密度。

方案 B

两行：标题一行，元信息一行（卡高 54）

第一行只有标题 + 时间，标题于是拿到整行（≈340px）； 第二行是 #标签 · 状态 · 删除，操作区不再是挤在行尾的那一小撮。

好处

  • 最好看、最像"卡片"：留白、层次、hover 面积都到位。
  • 标题宽了一点：≈300px → ≈340px（在浏览器里按同一套几何量的）。多出来的不多 —— 差别主要不在字数，而在层次与留白。
  • 标签有了正经位置，不再是一个 10px 的小片贴在行尾。

代价

  • 一屏只剩 4 张（254 ÷ (54+5) ≈ 4.3）。77 条那种量级要多滚一倍。
  • 想恢复 6 张就得把浮层上限从 288 抬到 ≈ 360 —— 它压住的转写区更多，要你点头。

变体 B′（不推荐，但列出来）

  • 第二行平时收成一枚「···」、悬停才展开 —— 省高度，但你们在删除按钮上踩过这个坑三次： 悬停才出现的东西会被当成不存在。要选它得先接受这条学费。

方案 C · 分组卡（今天 / 昨天 / 更早）

A 的密度 + 一层时间分组 —— 改的不是卡片长相，是"先看哪儿"。

方案 C

卡还是单行卡，按时间分组

组头像一行小字：今天 · 2 / 昨天 · 1 / 更早 · 3。 列表本来就是按时间排的，分组把"排序"变成"看得见的结构"。

好处

  • 一眼知道"刚才那几条在哪儿"，翻旧会话时不用看时间戳核对。
  • 与 A 不冲突：也可以只做 A、以后再加分组。

代价

  • 组头 20px × 组数：一屏从 7 张掉到 5 张。
  • 多一层结构要维护（分组的边界怎么算：24 小时 / 自然天？跨零点怎么算？）。
  • 会话少时（只有今天几条）组头反而是负担 —— 也许"只有一组时就不画组头"。

那些"特殊状态"在卡片里怎么画

下面这张图用的是 B 的卡（信息最多，最能看出各状态会不会打架）； A / C 同一套语义，只是挤在一行里。

状态 · 四档

当前 / 已打开 / 有标签 / 删除确认

  • 当前会话：左侧 3px 强调条 + 描边强调色 + 标题加粗。不用整条填色 —— 填色在 420px 里太重，会把别的卡压得看不见。
  • 被别的标签占着（已打开）：整卡压暗、标题转次要色、时间那格换成「已打开」（位置不变）。照搬现状的语义：点不动，但说得清为什么。
  • 有标签：#标签 chip；没有标签时留一个淡色「＋」—— 它是"给这条打标签"唯一的入口，不许藏。
  • 删除确认：卡片就地把内容换成问句 + [取消] [删除]，卡高不变（浮层不会跟着长）、默认焦点在「取消」上。

照旧不动的那几条

  • 双击标题改名、点标签改标签、点卡切换会话。
  • 忙时（权限待确认）整列不可点，删除入口不露。
  • 「删除」永远是文字，不是 ✕（这是你们 2026-09-15 定的）。
