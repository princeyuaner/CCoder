右键加进来的东西，怎么显示

现在右键「添加到 CCoder 聊天框」会把整段代码铺进输入框（路径 + 围栏 + 全文）， 选 30 行就顶掉 30 行；而且想引用一整个文件反而没有入口。这次要做两件事： 别全铺出来、以及支持右键加文件。

一条实测事实，它把方案空间收窄了

输入框里的 @路径 不是装饰 —— CLI 会自己把它展开成文件内容。 所以"加文件"这件事天生适合走 @：插件不读文件、不内联内容， 模型也不用自己动手读。

但带行范围的引用不成立。今天量的：@路径 展开（0 次工具调用）， @路径:24-27 不展开 —— 模型只好自己去 Read 了一遍整份文件。 所以"选区"不能用这条路，得另想办法。

两个轴，别混着选

轴一 · 显示层：输入框里那东西长什么样（一行记号／一整段代码／一行附件条）。 轴二 · 发送层：真正发给模型的是什么（@ 引用／展开成代码）。 下面四个方案是两轴的固定组合；你也可以各取一半，说一声就行。

要你拍板的三件事

  1. 显示层选哪个（A / B / C / D）。我倾向 C：它把"别全铺出来"这件事做到位，又不改模型真正收到的东西；加文件那一半走 @，正好复用已有的补全语义。
  2. 转写区里要不要也折叠。现在发送后整段代码会画进用户气泡（方案 B/C 的图里我先按"折叠成一张片段卡"画的）。要折叠的话，它是一次单独的改动（web 侧）。
  3. "加文件"的粒度：只加文件本身，还是允许"文件 + 行范围"（右键时若正好有选区）？我建议先只加文件 —— 行范围那条恰恰是实测不展开的那条路。

落地时要动的地方（按 C 算）

  • AddSelectionToChat.kt：拆成两个动作（加选区 / 加文件），后者在无选区时也可用；项目树那个入口是另一个 AnAction。
  • formatSnippet 一分为二：输入框里的一行记号、发送时展开的完整片段。两处都要单测（现有那几条钉在行号与围栏上，正好接着用）。
  • sendCurrentInput：发之前把记号展开 —— 展开表要跟着文本走，用户删字/粘贴之后不能错位。
  • 记号要上色（沿用补全那套引用色），并在悬停时给一句说明。
