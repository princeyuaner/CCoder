会话切换

恢复历史会话，列表挂在顶部状态栏。下面的模拟窗口都用探针从 ~/.claude/projects/ 取到的真实会话数据渲染 —— 包括那些 "11"、"你好" 之类的噪音会话，因为它们正是要判断的东西。

已定的事

列表挂在顶部状态栏右侧，点开弹出；不过滤终端会话（实测 includeProgrammatic: false 会把插件自己的会话一起滤掉）； 恢复语义是接着写（resume，不 fork）；当前会话打勾。

下面要看的是画法，不是语义 —— 语义已经定了。

一、状态栏那一行长什么样

现在这一行只有左边的状态文字，右边整片空着（ClaudePanel.kt:165）。 会话名放右边。四种状态都要能一眼看出区别。

状态 · 01

新会话

还没起过会话，或者刚点了「新会话」。没有 summary 可显示，所以用斜体占位而不是留空。

状态 · 02

已恢复的会话

标题就是 summary。超过宽度就省略号截断 —— 状态栏这一行不能因为一个长标题把「已连接」挤掉。

状态 · 03

回合进行中

状态点变黄、文字变「运行中」，会话标签变暗且不可点。切换要停掉 sidecar， 腰斩一个正在跑的回合还可能挂着权限卡片 —— 所以拦住，不是默默允许。

状态 · 04

四、取舍

选择好处代价
A · 单行紧凑 一屏放最多会话，扫时间最快 长标题会挤掉时间；PyCharm插件调用Claude Code 这种长度就开始省
B · 两行 标题不截断；能多带一个字段（条数、分支） 同样高度只能放一半；会话多了要滚动
C · 分支徽章 跨分支时一眼区分 本机 19 条会话全在同一分支，徽章变成纯重复 —— 建议先不做
拦截 · 点了才说 不懂的人点一下就知道为什么；说明与列表同时出现 多一次无效点击
拦截 · 一开始就说 少一次无效点击；状态栏已经把「运行中」写在左边了 点不动的东西容易被当成 bug
噪音会话不弱化 它们是真实历史，没有理由撒谎 列表里混着 "11"、"你好"，找东西靠扫

看完请回我三件事

  1. 排布选 A 还是 B？（C 我建议否掉 —— 分支字段在这台机器上没有信息量）
  2. 忙时拦住选「点了才说」还是「一开始就说」？
  3. 噪音会话要不要弱化？现在是不弱化，靠时间排序，你自己扫。
