四张状态卡片

连接状态、上下文、子任务、子代理 —— 这四样现在全挤在输入卡片内部的一行里， 而且子任务与子代理被合并成了右边一条 ◐ 3/7 名字 │ ● 2。 下面四种是把它们拆成独立卡片、挪到输入框上方的画法。

先说清楚约束 —— 这决定了四种画法为什么长成这样

  • 420px 宽，且输入区在底部、高度可拖。四张卡是竖着吃掉的高度，不是横着。一张单行卡 ≈ 32px，四张 + 间距 ≈ 140px。
  • 四样东西的"空闲率"差得极远。连接状态几乎永远写着"已连接"；上下文要等第一次 result 才有数；子任务要模型用了 TodoWrite 才存在；子代理要真有东西在跑。
  • 现有代码有一条明确原则：取不到就不显示，不造零值（runStripOf 返回 null 就整条隐藏，usageLabel 初始 isVisible=false）。一张写着"0/0"的常驻卡，比不显示更糟。
  • 子代理卡不只有子代理。现有 RunningTask 刻意把 local_bash（后台命令）也算进来 —— 注释写得很清楚：只按子代理设计的话，后台跑的命令会整个消失。下面的稿子都保留了这一点，标题叫「子代理」但内容是「在跑的东西」。

怎么选

四种其实是一条轴上的四个点：常驻多少、省多少高度。没有一种全赢 —— 差别只在你更受不了哪一样。

样式空闲占高忙时占高输入框会跳吗子代理名字看得见吗
A 竖排四张140px140px不会看得见
B 一排放四张50px50px不会看不见，只有计数
C 有内容才出现70px140px会跳看得见
D 芯片／展开28px28px 或 140px只在你点的时候点开才看得见

我倾向 B，除非你想看清子代理在干嘛。理由是那四样里 只有子代理是真的每秒在动 —— 连接状态基本恒定，上下文是慢变量， 子任务的进度条已经说清了 3/7。为一个大部分时候写着"已连接"的东西常驻一张卡， 是拿输入框的高度换一个不动的字。

但 B 有个硬伤：它装不下"explore 找出所有调用点"这种名字。 如果你会盯着子代理看，B 就不够，得走 A 或 D。 D 是唯一能同时给你"平时安静"和"想看时看全"的，代价是多一层可以点开的状态。

另外提一句 C 的副作用：它会让输入框在会话中途上下跳。 你正在打字、模型刚好甩出一个 TodoWrite，输入框就往下滑 70px —— 这类跳动在长时间会话里很烦。除非你要的就是"平时别烦我"，否则我不推荐 C。
