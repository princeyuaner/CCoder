上下文卡：点开之后看什么

你要的是「点开上下文卡 → 看到上下文的具体详情」。数据侧已经确认：SDK 早就在返回完整明细 （分类表 + 四张清单），只是 sidecar 现在只取了两个数，其余全丢。这一页要你挑的是"详情长在哪儿、长什么样"， 不是能不能拿到数据。三个方案都在真实的 420px 宽度里画，右上角可切深浅两色。

先说四条事实 —— 它们决定了三套方案差在哪

前三条来自 SDK 自己的类型注释（不是我推的），第四条是你们的既有约束。三张卡片同时出现， 是因为下面每一套方案都要照顾到它们。

FACT 01

数据早就在响应里

getContextUsage() 返回的不只是两个数：categories[]（每行 name / tokens / kind）、 mcp_tools[]、memory_files[]、agents[]、skills[]?，外加 over_limit 与 model。现在只取了 totalTokens 和 rawMaxTokens。

FACT 02

分类要按 kind，不能按名字

SDK 原话："Classify on this, never on the English name." —— 行名是 CLI 给的英文展示串 （Messages / System prompt / …）。三套方案里都按 used | free | buffer | deferred 判类。

FACT 03

deferred 不计入用量

deferred 行是窗口外的工具 schema（MCP 那些），SDK 明说"列出来只为知会，不进用量数学"。 所以它在条里不占宽度、求和时也不参与 —— 画错的话百分比和数字当场对不上。

FACT 04

没有逐条消息的明细

拿不到"这条消息吃了多少 token"。粒度的天花板就是上面那张分类表 + 四张清单。所以别把这一页设计成 "可以一条条翻账"的样子 —— 它做不到，会变成撒谎。

三套画法

三套用的都是同一份数据、同一套行样式（名字 · 细条 · token 数），差的是详情长在哪儿： 浮层、对话框、还是转写区里的一张卡。下面每张图都是"已经点开"的状态。

三件必须一起定的小事

这三条不定，上面三套画法都还是半成品 —— 而它们跟选甲/乙/丙无关，三套都要用。

其一

行名怎么翻（CLI 给的是英文）

分类行的 name、记忆文件的 type、子代理的 source 全是 CLI 给的 英文展示串。SDK 明确要求按 kind 判类、别按名字判 —— 但判完之后"写给人看的那几个字" 仍得自己出。两条路：

(a) 我们自己的键（中文界面出中文）

对话消息250.0k
系统提示12.4k
压缩预留33.0k
MCP 工具（窗口外）41.8k

代价：得维护一份英文名 → 键的映射；CLI 哪天改了措辞，那一行会静默退回英文 （不是崩，是"中文界面里冒出一行英文"）。

(b) 原样显示 CLI 的英文

Messages250.0k
System prompt12.4k
Autocompact buffer33.0k
MCP tools (deferred)41.8k

好处：零维护、永远跟 CLI 一致（与 `SystemNote` 的"Kotlin 侧拼好、web 侧不再翻"是同一类取舍）。 代价：中文界面里这一块恒定是英文。

（有个折中：认识的行给键、不认识的原样透传 —— 上面那种"静默退回英文"就变成设计的一部分， 而不是事故。要的是一份能容错的映射表，不是全有全无。）

其二

窗口外的东西（deferred）怎么画

它们不占窗口，所以不能进堆叠条、不能进求和；但"我有 12 个 MCP 工具、它们一共 41.8k" 本身是有用信息（决定要不要关掉几个）。画法建议：虚线细轨 + 一句"不占窗口"， 颜色压到 62% 不透明度，摆在"剩余空间"下面 —— 与上面几行拉开语义。

MCP 工具（窗口外）41.8k 不占窗口 —— 列出来只为知会

其三

超窗（over_limit）

响应里还带着 over_limit：超了多少、以及是硬顶（模型真装不下了） 还是压缩窗（策略设的 200K 之类）。今天这张卡只会变成红色百分比，说不清是哪种 —— 详情里应当用一句话说清，而两种的措辞要分开。

⚠已超出窗口 12.4k —— 达到模型上限，下一步请求会被拒绝
⚠已超出压缩窗 12.4k —— 还没到模型上限，但会自动压缩
数据形状来自 sdk.d.ts 的 SDKContextUsage（结构化版的 /context）； 三套画法里的数字是编的，但是自洽的：268k 已用 + 33k 预留 + 699k 剩余 = 1M， MCP 那 41.8k 在窗外、不进求和。
定了甲/乙/丙、以及"其一"走 (a) 还是 (b)，我就按这份写 spec。
