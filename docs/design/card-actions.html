清空 / 压缩：两颗按钮往哪儿放

诉求原文：「连接卡片里加个按钮，点击后清空本次会话；上下文卡片里加个按钮，点击后压缩上下文 —— 这样就不用敲指令了。」 功能本身两件都已经通了（`/clear`、`/compact` 都是现成命令，清空的整条路 0.2.13 就实现了）。这一版要解决的是 往哪儿放：一行 404px 里四张卡各 97×50px，v2 刚把卡面从 80px 收到 50px，两颗按钮得在这个数里挤出来。

已定 · 2026-09-17 选 甲（悬停换值）。四个决定也都拍了：忙时灰掉 · 压缩不带自定义指令 · 清空不弹确认框（danger 色）· 压缩回执接上「31.5k → 1.9k」。 落地规格：docs/superpowers/specs/2026-09-17-card-actions-design.md

约束一 · 空间

420px 窗宽 − 左右各 8px = 404px；四格等宽 + 3×5px 间隙 → 每格 97×50px。 卡面两行已经排满：图标 14 + 标签（最长 4 字≈42px）就占掉 60px。

约束二 · 有测试钉着

StatusCardsRowTest 里那条「八种连接文字都放得下」是量宽度的 —— 「等待响应」正是 4 字。 任何往标签行加宽度的做法都要先过它。

约束三 · 点击已各有归属

上下文 / 子任务 / 子代理三张卡的点击已经是"开详情浮层"；连接卡今天没有任何点击行为。 往上下文卡里塞按钮 = 与既有交互抢地盘。

约束四 · 语义两边不对称

清空 = 本地即刻完成（旧会话留在磁盘，能切回来）；压缩 = 一次模型调用，实测 ~10s （`compact_boundary.duration_ms:10165`），可被中断。一个瞬时、一个要等。

甲 · 推荐

悬停换值：值那一行变成按钮

卡静止时与今天一字不差；鼠标移上来，值行（「已连接」/「42%」）整行换成一颗按钮。图标 + 标签留在原处 —— 你始终知道自己在哪张卡上。零永久占位，也就零测试风险。

零。卡面一个字不动，宽度测试更不用管。

最多。可以带一行说明（"当前这条留在磁盘上"），压缩那侧还能顺手显示压缩前后的 token 数。

两步：点开卡 → 点按钮。想"省掉敲指令"，结果是省了打字、没省点击。

四个方案之外的四个决定

问题两面倾向
1. 忙时点得动吗？ 禁用：回滚那版同规矩（"回滚要在空闲时做"）；但 /clear、/compact 作为命令是 能进排队的（queued-input 版定的"照排，不特殊对待"）。
排队：按钮与敲命令行为一致，忙时也不挡。		 倾向禁用：压缩正在跑的会话语义暧昧（压的是"此刻之前"还是"跑完以后"说不清）， 清空则会把进行中的回合连根拔了。命令入口保持原样（照排），按钮走严格档。
2. 压缩要支持自定义指令吗？ /compact <说明> 可以带"保留什么"的指令。按钮发的是裸命令。
支持的话，需要多一层输入（浮层里给个输入框）。		 倾向先不带。真常用了再加：带参数的命令本来就能敲 —— 按钮服务的是"高频、无参数"的那一次。
3. 清空要确认框吗？ composer 版已定"不做确认弹窗"（误触代价低：旧会话在磁盘上，列表里能切回）。
但那是"打字"入口 —— 按钮入口误触率高一个量级。		 倾向仍不弹，但按钮用 danger 色 + 完成后系统提示照旧（"上下文已清空，这是一条新会话"）。 若你被误触过一次，随时补一个"行内二次确认"（会话列表删除那套，不新做模态）。
4. 压缩完的数字接不接？ 接：一条系统提示写清省了多少（31.5k → 1.9k），代价是新增解析 compact_boundary。
不接：卡上百分比自己会跳，但用户不知道"省了多少"。		 倾向接。这是唯一能让用户判断"这次压缩值不值"的信息，且数据已在事件流里。
