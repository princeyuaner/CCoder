Claude 提问时，卡片该长什么样

现在的做法是把 AskUserQuestion 当成普通工具：倒出原始 JSON，给两个按钮「拒绝 / 允许」。 可它的问题不是难看 —— 是那两个按钮表达不了"选哪个"。下面是四个结构上真的不同的方案。

先说清楚回传这条路

SDK 的 PermissionResult 支持 {behavior:'allow', updatedInput:{…}} —— 允许这个工具调用时可以改写它的入参。而 AskUserQuestionOutput 里正好有 answers: { [题目]: 选中的 label }，还能带 response（自由文本）和 annotations（备注）。类型定义层面这条路是通的。

但和"绕过权限能不能热切"一样：端到端我没验过 —— CLI 是否真的接受对 AskUserQuestion 用 updatedInput、并把它当成工具结果，得真机跑一次才知道。 如果这条路走不通，四个方案都还在，只是选项变成"点了替你回一句"，而不是直接回传答案。

方案 A

堆叠块

每个选项一块，标题加粗、说明在下，整块可点。 说明始终可见 —— 选项之间的差别往往就在那行小字里，藏起来等于没写。

一次问两个问题时，差别才真正显出来

一个 AskUserQuestion 调用最多可以带 4 个问题。这才是四个方案拉开距离的地方 —— A 和 B 是"全摊开"，C 会因为胶囊换行而开始失去结构，D 变成要点好几次。
