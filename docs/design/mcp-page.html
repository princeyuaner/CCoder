MCP 页：一台 server 一张卡片

右栏那张常驻表单撤掉 —— 页面就是一列卡片，一台 server 一张：卡头是名字与状态， 卡体是它长什么样（命令 / URL / 变量键名），卡脚是「编辑」「删除」，新增走弹窗。 今天那套「左 240px 列表 + 右 591px 表单」里，列表一行只够写个名字， 而状态得挤在另一张卡里（就是你截图里名字与状态叠住的那张）—— 卡片把这三样并成了一处。 下面两稿只差在卡片多高，弹窗两稿共用。

.mcp.json 认三种形状

命令行（stdio，不写 type）用 command / args / env； SSE 与 HTTP 用 url / headers。

写回时按原文件顺序重建、空字段不写；认不出的形状（sdk、claudeai-proxy） 原样保留 —— 今天它们在这页上完全看不见，这次给它们一张压暗的卡，把这件事说出来。

状态来自会话，不是文件

已连接 / 连接中 / 失败 / 已禁用，带工具数与失败原因（探针实测最常见的是 Connection closed 与命令找不到）。

它还包含你自己全局配的那些 —— 那些不在项目文件里，所以这页分成两段： 项目里的（可编辑）与全局的（只读）。两边对不齐是正常的。

卡片上不铺开的两种东西

环境变量与请求头的值：只列键名（GITHUB_TOKEN、LOG_LEVEL）。 这些值里常有 token，卡片是会被截图、被投屏的地方；要看值请开弹窗或看文件。

认不出的形状：只写"原样保留、插件不会动它"，不假装能编辑。

方案一 · 推荐

标准卡：三行说清一台

卡头（名字 + 形状 + 状态）／卡体（命令或 URL；变量键名；失败原因）／卡脚（编辑、删除）。 一屏大约放得下 4 台。

卡头
名字 + 形状标签（命令行 / SSE / HTTP）+ 状态（点 + 词）钉右。失败时点变红。
卡体
命令行那种：命令与参数连着写一行（等宽、可全选复制，长了换行）； HTTP/SSE 那种：URL 一行。变量与请求头只列键名。失败原因红字一行。
卡脚
「编辑」「删除」。删除是红字但不复选、不弹第二遍确认 —— 文件里有、git 里有，误删一次找得回来。
认不出的那条
今天它在这页上是隐形的（preserved 原样留在文件里，但用户不知道）。给它一张压暗的卡， 比"悄悄留着"诚实。
代价
比旧版占地方：旧的一行一台，一屏能看 8 台名字；现在一屏 4 台，但每台都看得见长什么样。 设备/服务器多了（10 台以上）要滚动 —— 方案二的紧凑卡就是为这个准备的。
方案二

紧凑卡：一台两行，动作钉在右边

第一行名字 + 形状 + 状态 + 两颗动作，第二行是命令摘要（超长走省略号，变量与请求头折进它尾巴）； 失败原因仍然独占一行红字 —— 那是"要不要去修"的唯一线索，不能省。一屏 8～9 台。

差别只有一处
标准卡把命令、变量、失败原因摊成三行；紧凑卡把它们挤进第二行（超长省略号）。 失败原因那条仍然独占一行 —— 它是"要不要去修"的唯一线索，不能省略号。
一屏几台
紧凑 8～9 台 vs 标准 4 台。你手上这台机器实测是 3 个项目 server + 2 个全局， 两稿都够用；紧凑卡是为"仓库里配了十几台"那种情况留的。
风险
第二行省略号之后，两台长得像的 server（同一命令不同参数）在列表里几乎分不出来 —— 标准卡不会。所以我推荐标准卡，紧凑卡留作"卡片数超过 8 台"时的退路。

我的建议

方案一（标准卡） —— 你手上是 3 + 2 台，占不满一屏，没有理由为省高度牺牲"两台长得像的能分清"。 与旧版相比，拆掉的正好是那张常驻表单，而它今天承担的"看"与"改"被拆给了卡片与弹窗，各归各位。

  1. 卡片流：.mcp.json 的每条 → 一张卡（卡头 / 卡体 / 卡脚）；＋ 是虚线占位卡； 全局与认不出的各一段（全局只读、认不出的压暗）。
  2. 状态并进卡头：从 McpStatus 那份会话状态里按名字取； 取不到（还没连上/不在会话里）就不画状态位，而不是画一个假的"未连接"。
  3. 弹窗：一套表单两处用（新增/编辑），底部 JSON 预览；「从模板开始」按你要不要决定去留。
  4. 用例：卡片渲染探针（三形状 + 失败 + 认不出的 + 全局只读各一张）、 卡头状态取不到时不画；键名列表与"值不铺开"那条各一条断言。

真机上要看的两件：① 卡片流在 10 台以上时的滚动与视觉噪声（要不要折叠成集团）； ② 环境变量只列键名这条，你实际用起来够不够（够就按这个做，不够我给个「显示值」的小眼睛）。

字段与规则取自 McpConfig.kt（三种形状、preserved 原样保留、按原顺序重建、空字段不写）、 McpStatus.kt（known 与"列表为空"是两件事）与 Protocol.kt 的 McpServerStatus（name / status / scope / error / tools）；旧版那半照着 build/probe/settings-mcp.png 描的。窗口尺寸（856×559）与真机一致；配色沿用 background-tasks.html 那一套。
