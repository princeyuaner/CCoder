MCP 页改版：新增走弹窗，右栏改成只读

今天这页是 左 240px 列表 + 右 591px 常驻表单，"添加"是列表卡页脚的一个标签 —— 点下去其实是"进入编辑态"，没有弹窗。要改三件事： ① 新增改成一个弹窗；② 右栏的常驻表单撤掉，换成只读详情（编辑也走弹窗）； ③ 顺手修掉「当前会话」那张卡里名字与状态在 240px 里撞在一起的老毛病。 三个方案在弹窗第一屏放什么上分岔，页面那半是三案共用的。

今天「添加」在哪

列表卡页脚一行 ＋ 添加 server。点它不落库 —— 它只是把右栏那张常驻表单切到"空白"， 名字（也就是 .mcp.json 的键）还没定，落库会写出一条无名记录，读回来时又被丢掉。

也就是说：今天根本没有"新增"这个动作，只有"进入编辑态"。

.mcp.json 认三种形状

命令行（stdio，不写 type）用 command / args / env； SSE 与 HTTP 用 url / headers。

写回时按原文件顺序重建、空字段不写（别塞 "args": []）；认不出的形状（sdk、 claudeai-proxy）原样保留，面板看不见它们，但改别的绝不能弄丢。

还有一份"状态"，来自会话

已连接 / 连接中 / 失败 / 已禁用，带范围（项目内 / 我自己全局配的）与工具数。它是会话的事实， 不是文件的事实 —— 左下角列的是文件里的，右边状态含你全局配的，两边对不齐是正常的。

失败时还有一句原因（探针实测里最常见的两种：Connection closed、命令找不到）。

一个既有缺陷

「当前会话」卡里，名字钉左、状态钉右，而这一栏只有 240px。两边都换行，一长就叠在一起 （下图 甲 里圈出来了）—— 与这次改版无关，顺手修：名字过长走省略号、状态钉右不换行， 失败原因另起一行（下图 乙 里就是这个样子）。

弹窗里放什么
与今天右栏同字段的表单：名称 / 形状（下拉）/ 命令 / 参数 / 环境变量；选 SSE·HTTP 时下半张换成 URL / 请求头。
为什么要 JSON 预览
这个动作的产物是要提交进仓库的文件。预览一行，用户就知道自己写的是什么形状、哪些空字段不会被写出去 —— 也不必再去翻 .mcp.json 猜。
字段校验
名称重复、命令为空、URL 不是 http(s) —— 都在当场说，「添加」置灰而不是点完没反应。
代价
右栏从"能改"变成"要看" —— 多一次点击才到编辑。换来的是列表 240px 里不再挤着一张常驻表单。
丙 · 弹窗第一屏是模板墙

先挑一个常见的，再改

页面与弹窗的第二屏与 乙 完全一样，只多第一屏：常见 server 的模板。 这一屏顺带把常见的坑写在脸上（npx 要 -y、github 要 token）。

为什么值得多这一屏
绝大多数人要加的就是那几个；模板把命令的准确写法（-y、@latest、包名）与前置条件 （token、浏览器内核、要装的运行时）一次说清 —— 这类"加上了但连不上"的求助，多半就出在这里。
代价
模板表要维护（每条：名字、命令、参数、说明、需要什么）。可以先放 4~6 条，用户报缺再添。
不做的事
不替用户装依赖、不去网上拉最新模板（那要联网 + 报错面大得多）；模板就是本地的一张常量表。
丁 · 弹窗第一屏是粘贴框

把抄来的那段贴进去，我拆成字段

同样落在 乙 那张表单上，区别是从哪来：适合从 README、文档、同事那儿复制配置的人。

新增 MCP server粘贴或手填
把 JSON 片段、或 claude mcp add … 那一行贴进来，例如：

claude mcp add --transport http context7 https://mcp.context7.com/mcp --header "CONTEXT7_API_KEY=xxx"
认三种写法：claude mcp add 命令行 · {"名字": {…}} 片段 · 整个 "mcpServers" 块（多台会一次全列出来，挑一台）。解析不了会说清哪一行的哪个位置看不懂， 不猜、也不静默丢掉。
下一步是一张已填好的表单，仍可改 取消解析
为什么值得
官方文档给的从来不是表单字段，是一行命令或一段 JSON。今天用户得自己拆到"参数（一行一个）"里， 而 args 的切分是带引号的（--header "X=1" 是一段，不是两段）。
代价
要写一个解析器（还有它的用例）。范围要钉死：只认这三种写法、不做 shell 变量展开、不做命令执行。
与 丙 的关系
同一张表单的两个入口（挑模板 / 粘贴）。先做 乙，两个入口后面各自加 —— 它们互不依赖。
方案弹窗第一屏新增一台要几步要知道字段含义吗抄来的配置落地成本
乙 · 表单表单5～7 个字段要自己拆小（一个 DialogWrapper + 校验 + 预览）
丙 · 模板墙6 张模板卡点一下 + 改名/填 token不用—中（多一张模板常量表 + 它的用例）
丁 · 粘贴大粘贴框粘一次 + 确认不用直接贴中（多一个解析器 + 用例）

我的建议：乙 做骨架，丙 的模板做弹窗里的一个小入口，丁 先挂账

三个方案页面那一半是三案共用的（列表 + 只读详情 + 状态并入），先干这个 —— 它顺带修掉那个重叠。 弹窗先按 乙 做（字段与今天那栏一一对应，风险最小），并在标题行右边留一个「从模板开始」的小入口： 点开就是 丙 那面墙，选完落回同一张表单。这样 丙 的收益拿到了，而模板表可以慢慢添。 丁 的解析器单独排 —— 它最有用，但也是唯一一个"要自己写解析器"的，别和主流程捆在一起。

  1. 页面改只读 + 状态并一行：详情卡（形状/命令/参数/环境变量 或 URL/请求头）+ 卡头状态 + 卡脚「编辑」「删除」； 列表行改成"名字 + 命令行 · 项目内"。顺手把那处重叠修了（有用例守着）。
  2. 新增/编辑弹窗：一个 DialogWrapper，字段同今天；名称重复、命令为空、URL 非 http(s) 当场说； 底部 JSON 预览。
  3. 模板入口：弹窗标题行加「从模板开始」，先放 4 条（filesystem / github / playwright / 自填）。
  4. 粘贴入口（另排）：解析 claude mcp add … 与 JSON 片段；范围钉死在三种写法。

真机上要看的三件：① 弹窗在 856×559 的设置框里不显得局促（字段挤不挤、预览要不要折叠）； ② .mcp.json 里混着 sdk 那类认不出的形状时，列表与详情怎么说（今天是不显示，建议加一行"1 条本插件认不出、已原样保留"）； ③ 加完一台之后要不要提示"下个会话才生效" —— 今天那句在右栏底部，进了弹窗就得重新找一个位置说。

这一页里的字段与规则取自 McpConfig.kt（三种形状、preserved 原样保留、按原顺序重建、空字段不写）、 McpSettingsPage.kt（MCP_LIST_WIDTH=240、"添加"只是进编辑态、状态卡的两栏布局）、 McpStatus.kt（known 与"列表为空"是两件事）与 Protocol.kt 的 McpServerStatus（name / status / scope / error / tools）；现状那半照着 build/probe/settings-mcp.png 描的。 窗口尺寸（856×559、列表 240px）与真机一致；配色沿用 background-tasks.html 那一套。
