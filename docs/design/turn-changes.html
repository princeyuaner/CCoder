本轮改过的文件：清单、对比、回滚

截图那张卡的三件事 —— 列出本轮改过的文件、在 IDE 里看改动前后、挑几个回滚。 清单这件事前端自己就能算（工具入参一直在转写流里）；真正的分水岭只有一个： 「改动前的内容」从哪来 —— 对比和回滚都靠它，而转写区里没有它。 这份稿先把这一件说死（第一节），再给界面三组选型（第二～四节）。

推荐组合（回一句「按推荐来」就行）： 机制 甲 · 侧车快照 ＋ 快照 落盘 · 卡片 甲 · 展开小卡（截图同款） · 选择 甲 · 复选框批量 · 确认 甲 · 卡内确认态 · Review 全开。文末有总表，可逐项改单。

现状与共同前提（都对着代码核过）

  • 清单不用新后端。toolFile / toolDelta / toolDiff（web/src/tools.ts） 早就在工具卡上算「哪个文件、+几行 −几行」；新卡是同一份口径的按文件聚合。 口径：只认 Edit / Write / MultiEdit / NotebookEdit， 且结果落地成功才计入 —— 被拒绝、失败的不算（工具结果里有 isError，转写区已按 toolUseId 配对）。
  • 轮次边界 = 最后一条用户消息之后。转写区已有这个边界的先例（Transcript.tsx 的 lastUserItemIdOf，用来给工具卡收尾）。 子代理的编辑也算「本轮改的」—— 它们的工具项本来就在转写流里。
  • 照不到的：Bash 里改的文件（sed / python 之类）。工具入参里没有文件信息，这是同类产品的共同盲区； 卡片文案照实说「编辑工具」，不装。
  • 旧的整条消息 ↺ 稿（docs/design/rewind.html）继续搁置。那是 CLI 检查点、整轮全文件粒度； 本稿解决逐文件。两者机制不同，互不替代 —— 丙案就是它，见第一节。
  • 忙碌时不能回滚（沿用旧稿：回滚要在空闲时做）；查看对比随时可用。
第一节 · 先把数据说死

回滚要有「改动前的内容」，它从哪来

三个来源、三种性格。先看对照表 —— 粒度这一列就把乙和丙堵死了：你要的是「选择回滚某些文件」。

机制甲 · 走这条

侧车快照 —— 编辑落地之前，先留一份原样推荐

抓手是 SDK 的 Options.hooks.PreToolUse：进程内的 JS 回调，带 tool_name 与 tool_input.file_path，在工具执行之前被调用。侧车在这一刻把文件读一份存档 （同一轮同一文件只存第一份 = 本轮开始前的样子）。

侧车（PreToolUse，先于工具落地） Edit / Write / MultiEdit / NotebookEdit ＋ 文件路径 → 读原样 → 存「会话 × 轮 × 文件」（同轮同文件只留第一份） 回滚 = 把存档写回；存档时文件不存在 → 回滚就是把它删掉 对比 = 左：存档　　右：磁盘上的当前文件

能：逐文件、准确、能如实标「新建 / 删除」 代价：新存储 + 两条协议；单文件上限要定

唯一的未知先钉死：hook 在 bypassPermissions / acceptEdits 这类「不询问」的模式下是否照常先于执行触发 —— 旧探针只验过默认模式（probe-mcp-hooks.mjs 事实 5）。实现前先跑文末探针清单第 1 条； 若某模式不触发，退路是「assistant 消息到达时抓」，接受一个极小的竞态窗口，并把这条写进已知未知。

机制乙 · 不做

转写反推 —— 零基建，但会在最需要它的时候掉链子

「看着能做」正是它的危险之处：十个文件里九个回得去，第十个是 Write 覆盖过的文件 —— 旧内容没在任何地方。 做到一半失败、或者悄悄换错地方，比不让点严重得多。这条否决：做不了就明说，不做"薛定谔的回滚"。

机制丙 · 不进 v1

CLI 检查点 —— 整轮全文件，与「挑几个」正面冲突

旧稿的机器，探针事实都还在（sidecar/tools/probe-rewind.mjs 可重跑）：整轮粒度、跨会话可用。 它有一件甲做不到的事 —— 连 Bash 改的、清单漏掉的也一起回到那一刻。将来真有人要「整轮全部回滚」这个语义，再谈它； 这份稿不动它。

甲的内部决定 · 存档活多久

内存 or 落盘

不选「逐轮全量保留」：存档只在最新一轮有用，轮次一翻页，旧存档就该淘汰。

甲a · 只活会话（内存）甲b · 落盘推荐
重启 / 换去又换回之后 卡还在（清单能从转写区回放重建），但对比和回滚都没了 —— 行全部标「无存档」 对比、回滚照常 —— 恢复会话的最后一轮一样可操作
存哪 / 上限 实现最轻，什么都不落 app 级目录，按 项目 + 会话 分（键法现成：sidecar/project-key.js）； 单文件 ≤ 2MB、每会话保留最近 20 轮，超限的行标「未存档」；设置里一颗开关（默认开）

第五节 · 边界（每态都有一句话，不静默）

出问题的地方，才是承诺真正落地的地方

情况表现
会话忙（Claude 还在跑） 回滚入口禁用（悬停一句话：「等它停下来再回滚」）；对比随时可看。
本轮没有文件改动 卡片不出现 —— 不占地方、不假装有事发生。
Bash 改的文件 不在清单（共同盲区）。卡片头副标题写「编辑工具改过的文件」，照实说。
无存档（开关关着 / 超 2MB / 老轮次） 行标「无存档」：点击只打开文件（没有对比），勾不了、回不了。原因进悬停提示。
本轮结束后文件又被改过 确认态里那一行加一句「本轮后有新改动，会被一并覆盖」—— 不替用户决定，只把后果说白。
回滚时写盘失败 / 文件已被外部删掉 逐文件红字原因 + 系统提示汇总：「已回滚 1 个文件，2 个失败」。失败的行保持可勾选，重试就是幂等的。
想回滚更早的轮 不做（卡片只活在最新一轮）。工具卡还在，那上面能看 diff，但回不了 —— 说清，不装。

探针清单 · 已跑（2026-10-13）

探针证明的是它真跑过的那一件事

第 1～5 条已实测成立（三种权限模式下 hook 都先于执行、同轮第二次读到已改内容、 Write 新建时文件不存在、零副作用、resume 照常）；子代理的编辑也触发（带 agent_id）。 另有一支集成探针把整条链跑通：真模型改文件 → 快照 → 回滚 → 逐字节核对。 事实表与结果在 docs/superpowers/specs/2026-10-13-turn-changes-spec.md §1 与 §8。

#要钉的事实
1Options.hooks.PreToolUse 在 默认 / acceptEdits / bypassPermissions 三种模式下都先于工具执行触发，且 tool_input.file_path 在。
2同一轮同一文件两次 Edit：第二次 hook 时读到的是第一次改后的内容（证明「只留第一份」= 改动前）。
3Write 新建文件时，hook 那一刻文件尚不存在（「回滚 = 删除」的依据）。
4hook 回调返回空对象不影响工具执行、不产生任何可见事件（副作用为零）。
5会话恢复（resume）之后，新轮的 hook 照常触发；存档索引能读回。
6平台侧：DiffManager / SimpleDiffRequest / DiffContentFactory.createDocument 在目标 IDE 版本可用；左侧内容不落盘可行。
7外部改写 / 删除文件之后，VFS 与已打开的编辑器能及时跟上（IDE 本来就天天接 CLI 的外部写，这条是确认不是新开）。
8全链路真机：跑一轮（两次 Edit ＋ 一次 Write 新建）→ 回滚 → 逐字节核对 ＋ 新文件被删。

测试层：web 纯函数单测（口径与边界：被拒的、无结果的、子代理的、NotebookEdit、Write 新建）· sidecar 单测（快照策略、上限、回滚回执分类）· 渲染探针（卡五态出图，出图要真的打开看）· 集成探针（第 8 条）。
