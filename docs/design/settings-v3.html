设置界面改版四个方向 · 选一个再细化

现状 真机渲染 · 860×560

这三张是用渲染探针从真实 Swing 组件画出来的（SettingsDialogProbe），不是示意图 —— 就是你装到 IDE 里看到的样子（探针跑在浅色主题下，真机会跟随 IDE）。

  • 左栏是一列纯文字：没有图标、没有分组，选中态是整宽的一条底色。八个页签看着像一张清单，不像导航。
  • 字段一路往下堆：标签上面、输入框下面，控件宽度各不相同，右边空出一大片；八页里没有一处「这几项是一组」的暗示。
  • 灰色说明连成串：它们与字段等宽、字号接近，读起来像正文；页与页之间只有内容不同，长相完全一样。

A · IDE 原生 改动最小

把设置框做成「IDE 自己那套设置」的样子：左栏分组 + 图标导航，右侧标签在左、控件右对齐成一列，说明挂在控件正下方。

  • 导航：分两组（配置 / 其他），每个页签一枚 16px 图标；选中是圆角块，不再是整宽的方条。
  • 字段成为栅格：标签列固定 180px，控件列固定 400px 右对齐 —— 控件第一次对齐成一条线。
  • 说明跟着控件走：灰色小字挂在它说明的那个控件下面（现在挂在字段之间，读起来像正文）。
  • 页脚不动：还是「改动即时保存」+ 关闭。
  • 代价：小。左栏加图标与分组 ≈ 一个 navItem()；labeledField 换成 settingsRow()（两列布局），八页都能原样套。
  • 新文案：两个分组标题。风险：低。

B · 卡片分区 层次最清楚

字段按语义装进卡片，一张卡一个主题；导航的选中态是实心的强调色胶囊。

  • 卡片：圆角 8 + 1px 边 + 一枚卡头标题。通用页恰好分三张：运行环境 / 会话默认值 / 界面。
  • 卡内成行：左边标签（说明挂在标签下），右边控件右对齐 —— 长说明不会把行撑歪。
  • 危险动作单独收尾：删除进卡片的脚部、红色，不再跟字段混在一列里。
  • 列表 + 表单也成卡：模型页左卡「配置」，右卡就是正在编辑的那一条。
  • 警告也进卡的语言：冲突提示是一条淡黄底的小条（模型页那张图里能看到）。
  • 代价：中。圆角卡片要自绘（本仓库已有现成做法：状态卡就是 paintComponent 画的圆角面板）；分组本身是纯摆放。
  • 新文案：卡片标题若干（通用 3、模型 2、其余页各 1-2），估 8-10 条键，中英两份。
  • 风险：卡多了页就长，要滚动；长说明会把卡撑高。

C · 顶部页签 内容最宽

扔掉左边那 140px：页签横到顶上，内容整宽，短字段两列并排。和转写区那几个页签是同一个语言。

  • 页签带下划线指示条，悬停才有底色；不再有"一整条方条"的选中态。
  • 多出 140px：两列并排也放得下（发送快捷键 | 思考深度），长路径与说明不再挤在 448px 里折行。
  • 分节用「小标题 + 一条横线」，不画卡片 —— 追求的是"文档感"，不是"仪表盘感"。
  • 列表页照旧两栏，但右栏宽了一大截：Base URL、模型 ID 这些长串终于能一行放下。
  • 代价：中。导航从竖改横是外壳的事（tabsColumn() 换 tabsRow()）；各页那几个"固定宽表单栏"的常量要重算（PAGE_WIDTH 那套 +140）。
  • 风险：页签以后再加就会横向挤（现在 8 个正好）；两列要对齐整齐，对不齐比一列更乱。

D · 紧凑双列 一屏看全

给老手的那一版：一页读起来像一张三栏的表 —— 标签、控件、说明各占一列，行高 27px，一屏看得完更多设置。

  • 三栏表格：标签右对齐、控件紧跟在它右边（不再右对齐到一条线），说明收成最右边一列 11px 小字 —— 不再占段落，也不再跟字段抢宽度。
  • 行高 27px：整页一眼扫完，眼睛沿标签列往下走。
  • 等宽体给路径与模型 ID：deepseek-flash[1m] 这种一眼看清括号后缀。
  • 模型 ID 变成真正的列表行：每行一个、"设为在用"是个动作，而不是一串长得一样的输入框。
  • 代价：小-中。就是栅格改写 + 提示语挪位置；wrappedHint 在通用页会基本消失 —— 但权限页那几句说明是安全声明，别收进 ⓘ，那一页照旧整句写出来。
  • 风险：密。对"怕看漏"的人不友好；收进 ⓘ 的话不容易被发现。

并排比较 都是通用页

四个方向放在一起看。差别主要在四件事上：导航长什么样、字段怎么排、说明放哪儿、有没有分组。

  • 想风险最小、最"像 IDE 自己的设置" → A
  • 想层次最清楚、最好看 → B（代价：自绘圆角卡片）
  • 嫌内容太窄、长路径老折行 → C（代价：导航从竖改横）
  • 老手、想一屏看全 → D（代价：说明要收，权限页那几句不收）
  • 我的偏好：A 的导航 + 行栅格，配 B 的卡片分组（只在通用 / 权限 / 环境这类纯表单页用卡）。你要是点头，我按这个混合出一版细化稿。

这些 mockup 是 HTML 画的示意图，不是 Swing 渲染 —— 方向看它，落到真机上字体、圆角、控件高度会有细小差别。mockup 里的字除卡片/分组标题外都是从词表里抄的；新文案（分组标题、卡片标题）要进词表，中英两份。
