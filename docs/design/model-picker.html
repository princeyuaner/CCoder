模型切换弹层该长什么样

今天的弹层（变体 0）只有三层灰：组头、模型行、「管理模型」都挤在同一档次要色里， 选中只靠一个 ✓ 和加粗，没有悬停，会重开会话 挂在最右边像装饰。 下面五种改法都能落地到 ComposerModel.kt，宽度一律按真实的 442px 画。

👉
模型行是可以点、可以悬停的真行 —— 点一下就能在几套样式之间来回试选中态。虚线是工具窗口的 420px 边界，弹层比它宽是现状，不是画错了。

变体 A

精修原版

成本 低

结构一行不动，只把层级、选中态和悬停补出来：组头退成等宽小字，选中行有整行底色 + 左侧 2px 主色条，警告前面加一颗琥珀色圆点，管理行用一条发丝线隔开。

工具窗口 420px
deepseek-flash[1m] ▾ 标准 ▾
➤
好在哪
  • 最像 IDE 原生控件，跟旁边的权限弹层、补全弹层是同一族
  • 选中行的底色让「我在哪」变成余光可见，不用逐行找勾
  • 悬停 → 底色一亮，可点这件事不用教
  • 改动最小：行高、分组、文案一个都没变，回归面最窄
代价

  • 组头用等宽字体是新引入的（不想要就换成小一号常规字，效果差不太多）
适合
2–3 个网关、每网关 1–3 个模型 —— 也就是你现在这个规模。
变体 B

分组卡片

成本 中

一个网关一张卡：组头变卡头（名字加粗 + 主机名跟在后面），「会重开会话」缩成头上一颗琥珀描边胶囊，卡片之间留 8px 空隙。三个网关一眼就是三块。

好在哪

  • 警告胶囊有了边框和底色，终于像「跟你有关」而不是装饰
  • 选中行多一道主色内描边，跟「当前配置」分得比 A 更清

  • 弹层自己也是圆角面板，圆角套圆角，边距调不好会显脏
适合
3–6 个网关、且你希望「先选公司还是先选模型」这件事在视觉上先发生。
变体 C

自述行

成本 中

每个模型占两行：上面是模型名，下面用小字写清它是谁家的、打到哪台机器，右侧跟一句琥珀色的「会重开会话」。组头退成一条带标题的发丝线 —— 因为每行已经自己说清楚了。

好在哪

  • 两行行需要重设命中区（整行都要可点，不能只点第一行）
适合
网关多、名字像（好几个都叫「中转」）的时候；或者你常忘了自己在哪个端点上。
变体 D

紧凑高密度

成本 低

行高压到 25px，选中整行填主色（白字），[1m] 剥出来做成小片挂在右边，重开后果缩成一颗 ⟳，鼠标停上去出提示。信息最密、最「工具」。

变体 E

色带分段

成本 低

每个网关左边一条3px 色带，组头用同一个颜色，模型行缩进排在色带右侧。颜色按顺序自动分配（蓝 / 青 / 紫 / 橙），不需要你去设置里挑色。

➤
好在哪

  • 眼熟 —— 树、时间线、输出分组都用这个手法
  • 容易叠在 A 上：A 的底色 + E 的色带 = 层级和分组兼得

适合

已选定：B 分组卡片（2026-09-21）

原来的建议是「以 A 打底、把 E 的色带叠上去」，最后选的是 B。 已实现到 ComposerModel.kt，真 Swing 的离屏渲染在 build/probe/composer-model-popup.png（浅色）与 -popup-dark.png（深色）—— 以后再动这处观感，先看那两张图。

实现时与这份稿子有三处出入，都是有意的：

  1. 卡片底色就是弹层面板色：卡靠边 + 圆角 + 8px 缝立起来，不靠色差。稿子里卡比背景亮一档，那是浏览器里弹层底透明的画法；Swing 的弹层自带底色，做成半透明要跟平台的弹层边框打架，不值当。
  2. 主机名没引等宽字体 —— 那要往 UI 里拉一个新字族，而"小一号 + 次要色"已经够分主次了。
  3. 勾是单独一个标签（原来缀在名字前面），为的是让它能用强调色；相应地 ComposerModelTest 里那条断言改成看"勾落在哪一行里"。

另外：行高、勾位、卡片内边距都会改宽度，MAX_HOST_CHARS 是在卡片版下用 ComposerModelRenderProbe 重新确认过的（弹层不会比工具窗口宽 那条测试守着它）。
