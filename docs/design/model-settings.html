CCoder · 设置入口 · 模型配置

多模型配置与切换

三条需求：右上角一个设置齿轮；点开是带页签的设置，其中一页管多个第三方模型； 输入框左下角的模型标签能直接点开切换。 下面是三种放法 —— 差别在设置放在哪，不在于好不好看。

两个硬约束，决定了图上为什么这么写

① 模型是会话启动参数，不是运行时开关。 它由 ClaudeSettings.toStartParams 打包进 start 消息， sidecar 那边 session.js:88 塞进 SDK 的 options.model。 所以切模型 = 重开会话，当前上下文不保留。 三张图上都留了这句提示 —— 少了它，用户会以为切完还能接着聊。

② 工具窗口只有 420px。 这是真宽度（.tw 就是这个数）。一条 Base URL 平均 36 字符， 等宽字体下在 420px 里必然折行 —— 方案 B 把这个代价直接画出来了。

顺带一提：项目已经有一个原生设置页

ClaudeSettingsPanel : Configurable，注册在 plugin.xml:15 的 <projectConfigurable>，现有六项设置都在那儿。 方案 A/B 是另起一套自己的 UI，方案 C 是复用它 —— 齿轮只当做个快捷入口。 这三条路的成本差着量级，选之前值得知道。

怎么选

　方案 A · 模态三栏方案 B · 窗口内嵌方案 C · 原生 Settings
字段能不能完整显示能，不折行URL 折两行能
离开工具窗口会不会会
页签外观能自己定能能平台说了算
要不要新写对话框架构要不要不要
和后加的页签（通用/权限…）合住天然合适挤，420px 放不下第三排本来就是

我推荐方案 A。 三条理由：你要的是「点开是一个个页签」—— 这是个会长大的容器， 以后还会加通用、权限、快捷键，而 420px 塞不下第三次扩张； A 的字段不折行，Base URL 和 API Key 这两个最怕折行的东西正好是最长的； 页签在左侧和 PyCharm 自己的 Settings 一致，用户不用学新东西。

代价是得写一个 DialogWrapper。但方案 B 省下的那点功夫， 会以「每次加页签都要重新腾地方」的形式还回去。

方案 C 值得单独考虑一次 —— 如果这套设置注定只有你自己用，不打算给别人装， 那复用它几乎零成本，只是拿不到你要的那个「页签式」外观。 这不是技术取舍，是你想让这个插件长成「PyCharm 的一部分」还是「自带一整套 UI」。

有一件事无论选哪个都不会变：左下角那个标签照 ModeLabel 做， 点开弹层、当前项打勾、底部一条「管理模型…」。这部分是共用的，可以先做，不依赖上面的选择。
