CCoder · 输入区 · 设计稿

贴图：截图直接发给 Claude

现在往输入框里粘一张截图，什么都不会发生（那是个 JTextArea，只认文字）。 下面是四套做法，差别集中在两件事上：待发时占多少地方、 发出去之后这张图长什么样。

先说四条事实

01

路是通的，不用发明协议

SDKUserMessage.message 就是 Messages API 的 MessageParam， sdk.d.ts:5464 的原话：content is a string or an array of content blocks (text, image, document, …)。今天传的是纯字符串， 要改的是"把它拼成数组"。

02

只有一处要改协议

用户这一条消息在 sidecar/session.js 里拼；Kotlin 到侧车的 JSON 加一个 images: [{ mediaType, base64 }] 就够。 转写区那边再多一条 op（把图推给页面渲染）。

03

转写页读不到你的硬盘

页面是 loadHTML(html) 装进去的（没有 base URL）， 所以图只能当 data URL 推过去；不能"传个路径让它自己读"。 这也意味着同一张图会同时活在两三个地方。

04

一张全屏截图 1–3MB，base64 后 +33%

所以四套方案真正的分水岭是：推给页面的是"缩过的小图"还是"原图"。 缩略图那条路要写一次缩放（Graphics2D 画一张 56px 的）， 换来的是一条 2KB 级的 op，而不是 4MB 的字符串过桥。

二、四套共用、不用选的两件事

共用 · 放大

点一下，在面板里放大看

四套都长这样：一层压暗的浮层，图按面板宽度铺满，Esc 或点空白关掉。 不做"在编辑器里打开图片"—— 那要落一个临时文件，还得管清理。
