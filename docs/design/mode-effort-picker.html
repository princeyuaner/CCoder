权限模式与思考深度：这两个弹层该长什么样

它俩和刚换过样式的模型弹层并排站在同一行里，所以问题不只是"好不好看"， 还有"三个弹层像不像一家人"。今天的两个弹层共有的毛病：没有悬停、 选中只有勾和加粗、十二行灰字一样重，而「绕过权限」那句最该被看见的 危险说明，就埋在这片灰里。

👉
每一行都可以悬停、可以点 —— D 案的底部说明条会跟着鼠标走，点一下就能试。两个弹层的行是同一套样式，这是有意的：它们本来就是一族。

为什么拿它当尺子

它昨天刚定稿（B 分组卡片）：卡片分组、30px 行、勾位 + 悬停底 + 选中底 + 强调色勾。 这三个弹层会连着被点开，样式差一档就会立刻看出来。

所以下面每个方案都同时画权限模式和思考深度两个弹层 —— 一个方案只在其中一个上好看，不算数。

方案 0

现状

baseline

照 buildModeList / buildEffortList 今天的画法复刻：名字一行、说明一行，勾是文字前缀，选中加粗，其余一视同仁。

方案 A

同族精修

成本 低

一行结构不动，把模型弹层那套行的做法搬过来：固定勾位 + 悬停底 + 选中底 + 强调色勾。两个字读起来更清楚 —— 名字是常规文字色，说明退一档。

好在哪
  • 零新概念：和模型弹层是同一套行，三个弹层连起来点像一家人
  • 选中一眼可见（底色），不用逐行找勾
  • 改动只在绘制层，modeColor 那些判定一个字不动
代价
  • 「绕过权限」还是只靠一行琥珀色的名字，没有别的分量
  • 十二行仍然平铺，档位高低、问不问，还得逐行读说明
方案 B

右列标记

成本 中

在 A 的基础上，右列加一个"这一行是什么性质"的标记：权限用词（会问 / 只读 / 不问 / 危险），档位用条（五格竖条，越高档亮得越多）。两个列表的标记不同，因为它们要说的本来就是两件事。

好在哪
  • 不用读说明就能扫：一眼看出哪几档是"会问你"的、哪几档是高的
  • 危险那档有了一个专属的琥珀胶囊，跟模型弹层的〔会重开会话〕同一个语言
  • 档位条把"低→最大"这条阶梯画出来了 —— 说明里那句"仅部分模型认"才有落点
代价
  • 右列要新画三样东西（胶囊、竖条、问不问的标），比 A 多一份绘制活
  • "会问 / 只读 / 不问"是我替每一档归的类，算新的判断，得你认一下
方案 C

卡片分组

成本 中

直接用模型弹层那套卡片，把两个列表各切一刀：权限分成「会先问你」/「不再问你」，档位分成「通用档」/「仅部分模型认」。都不重排 —— 刀口落在列表本来就有的那道缝上（枚举顺序里 4/5 之间）。

好在哪
  • 三个弹层完全同族：同样的卡、同样的行、同样的勾位
  • 把"说明里的小字"变成"结构"：极高/最大那两条的小字警告，现在是整张卡的标题
  • 危险那一组自带琥珀卡头，绕过的分量终于对得上它的后果
代价
  • 要新增一个"这条属于哪一组"的判定（groupOf），并给它写测试
  • 卡片要多占约 45px 高；分组标题是我拟的词，得你认
  • "仅规划"归在「会先问你」那一组 —— 严格说它是"根本不用问"，措辞要么改要么忍
方案 D

紧凑单行 + 底部说明条

成本 低

列表只留名字（26px 一行），说明挪到底部一条：默认显示当前这档的说明，鼠标划过哪一行就换成哪一行。十二行灰字压成六行名字 + 一句说明。

好在哪
  • 最省地方：6 行从约 230px 压到约 190px，两个弹层都不占屏幕
  • 一次只读一句说明，眼睛不用在两列文字之间来回对
  • 危险那档划过时，底部整条说明变琥珀色 —— 提示落在要点的那个动作上
代价
  • 说明是"挑模式"的主要依据，藏到悬停后面有发现成本（默认只显示当前档那句）
  • 两个弹层各自多一个会变的标签，比 A 多一处状态

已选定：C 卡片分组（2026-09-21）

已实现到 ComposerMode.kt / ComposerEffort.kt。三处弹层共用的那套 "卡与行"抽成了 PickerList.kt —— 样式只写一遍。 真 Swing 的离屏渲染在 build/probe/composer-mode-popup.png 与 composer-effort-popup.png，动这处观感之前先看它们。

组名定的是：权限「常规 / 不再问你」，档位「通用档 / 仅部分模型认」。 第一组不叫「会先问你」——「仅规划」是只读、根本不执行工具，说它会问是反的。

实现时踩到并修掉的两个坑（都不在稿子的视野里，记在这儿免得下次再踩）：

  1. 鼠标事件不冒泡：一行里几乎每寸都被子标签盖着，悬停只挂在行自己的话，鼠标压在文字上这一行不亮 —— 而探针是直接喊监听器的，看不出这类问题。现在悬停挂到整棵子树上，并由一条单测钉住（鼠标压在文字上这一行也要亮）。这条同时修好了模型弹层那边的同一处毛病。
  2. 勾位在横向 BoxLayout 里会吃掉富余宽度，把名字顶到行右端。preferredSize / minimumSize / maximumSize 三样得一起钉。

另外补了两条宽度上限测试（两个弹层原先都没有），照模型弹层那条的样子写的。
