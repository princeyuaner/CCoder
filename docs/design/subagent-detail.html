子代理浮层：把重复的那一段拿掉

点「子代理」卡弹出来的那个浮层。你说信息太多 —— 拆开看，多的不是细节， 是同一批人被列了两遍，而下面那一遍天生只有名字。

先把问题说准

那个浮层现在画两段（RunDetail.kt:142 的 buildRunningDetail）： 「运行中」用的是 RunningTask，每条两行 + 右侧统计 + 一颗终止方块； 「全部子代理」用的是 SubagentInfo，每条只有"类型 描述"一个标签。

  • 重复：正在跑的那几条在第二段里又出现一次 —— 而 SUBAGENTS_SECTION 的注释自己写着"还在跑的子代理同样在这一段里"。
  • 第二段天生就这么瘦：SubagentInfo 只有四个字段（agentId / agentType / description / toolUseId）—— 没有 token、没有耗时、没有状态。所以它不是排版没排好，是数据里就没有。
  • 但它不能删：点一条回看它的转写，是目前唯一的回看入口（RunDetail.kt:264 那段注释）。

于是要解的就两件事：①同一批人只说一遍；②第二段收成一条能点开的线， 而不是两段摊开。空闲时其实已经这么做了（historyExpanded 那条 "看已结束的 N 个 ›"）—— 只差在"有在跑"的时候没这么做。

选型结果：方案甲（2026-09-24）

实现时按真机改了四处，都是效果图上看不出来、做的时候才撞上的：

改了什么为什么
右下那排"快照条"不做了 数据里只有计数、画不出真进度，画满会被读成进度条 —— 那是编出来的进度。卡上那个活点就够了。
描边用常态色，不用强调色 这一版里每张卡都是在跑的，每张都强调等于没强调。"在跑"由"这是一张卡"这个形态本身说。
卡片上限 4 张，超了说一句 量出来的：3 张卡 + 那条线 267px、4 张 + "还有 N 个在跑" 359px，而工具窗口首选高才 600、 浮层还是向上弹的。超了不画那几条明说（状态卡上的数才是权威）。
记录 = 对不上在跑任务的那些 SubagentInfo 没有状态字段，只能拿 toolUseId 去 RunningTask.id 里找。 对得上就是在跑（已经在上面某张卡里了），对不上就是记录 —— 重复就是这么消掉的。
那条线展开之后也留着 顺带修一个旧毛病：从前只在收着时画，展开就再也收不回去（只能关掉浮层重开）。 一个只能进不能出的开关不是开关，所以展开时它写成「收起」。

出图看效果：build/probe/running-detail-cards.png（卡 + 记录）、 -cards-over.png（超上限）、-cards-hover.png（悬停）。 过程中从图上逮住两个自己写的排版错，都是 BoxLayout 交叉轴那条老规矩： 同一条 BoxLayout 里所有子件必须共用同一个 alignmentX， 混进一个 0.5 就会把窄的那些（详情行、统计行、"还有 N 个"）摆到中间去。

落地约束：这一屏是 Swing，不是网页

上面这些是效果图，真做的时候是 Swing 画的。同一个观感，代价差别很大：

想要的在这套代码里代价
圆角描边卡RoundedLineBorder（RunDetail.kt:44，聚焦只换色不加粗）低 —— 已经有人写好了
卡底色比面板亮一档取 UIUtil 的文本框底色，或按明暗方向偏移（surfaceFor 那套）低
左侧强调条 / 底部统计带自绘 —— paintComposerFooter 的"圆角矩形 ∩ 直角矩形求交"就是干这个的中（要写 paintComponent）
活点 / 悬停提亮TaskStopButton 是现成的自绘模板（preferredSize 钉死 + 悬停提亮 + repaint）中
阴影、渐变、hover 过渡动画没有先例高 —— 建议不做，卡靠描边与底色分层就够
两栏流式布局BoxLayout 换 GridLayout，交叉轴对齐那套得重看高（且方案丁本身也不成立）

另：那一屏的高度必须有上限 —— 浮层是挂在面板底部那张卡上的（ showAboveOrBelow），长到顶出屏幕就点不着了。现成做法见 buildSubagentDetail 里那块 380×280 的限高滚动区。

选型建议

甲（逐条卡）最贴你说的"卡片式"，而且它顺手解决了那个真问题：卡 = 在跑、线 = 记录， 不用读小标题就分得清。它比乙贵在自绘，但圆角描边与悬停这套零件仓库里都有现成的。

想先小步走就选乙：它删掉的东西和甲一样多（整段重复 + 一个小标题）， 只是没把"卡"做出来，改动面最小、最容易验。

丙值得留着做第二步：等哪天在跑的子代理真的到 6 个以上，"抬头那一个数"会比一张张卡更管用。 丁不建议。
